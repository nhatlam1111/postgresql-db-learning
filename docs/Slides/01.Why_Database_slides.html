Database (Cơ sở dữ liệu)

Giống nhau

Khái Niệm 2: Table = Sheet

Mỗi Table trong database tương đương với một Sheet trong Excel:

📊 Sheet "Nhân viên" (Excel)

  A    │      B       │      C
──────┼──────────────┼───────────
  1   │ Trần Thị Mai │ Kế toán
  2   │ Nguyễn Văn An│ Kinh doanh
  3   │ Lê Thị Bình  │ Nhân sự

🐘 Table "nhan_vien" (PostgreSQL)

 id  │    ho_ten    │  phong_ban
─────┼──────────────┼───────────
  1  │ Trần Thị Mai │ Kế toán
  2  │ Nguyễn Văn An│ Kinh doanh
  3  │ Lê Thị Bình  │ Nhân sự

Sheet trong Excel

  • Có thể chứa bất cứ thứ gì — công thức, biểu đồ, text tự do
  • Cột dùng chữ cái A, B, C...

Table trong Database

  • Chỉ chứa dữ liệu có cấu trúc nghiêm ngặt
  • Mỗi cột bắt buộc có tên rõ ràng và kiểu dữ liệu
  • Mỗi table = 1 chủ thể: nhân viên, sản phẩm, đơn hàng...

Khái Niệm 3 & 4: Column = Cột, Row = Hàng

📊 Column = Cột (A, B, C...)

Trong Database: cột bắt buộc có tên thay vì A, B, C:

  • ho_ten → chứa họ tên
  • luong → chứa mức lương
  • ngay_sinh → chứa ngày sinh
  • email → chứa email

📊 Row / Record = Hàng

Mỗi Row là một bản ghi hoàn chỉnh về một đối tượng:

 id │    ho_ten     │  luong
────┼───────────────┼────────────
  1 │ Trần Thị Mai  │ 15,000,000 ← ROW 1
  2 │ Nguyễn Văn An │ 20,000,000 ← ROW 2
  5 │ Hoàng Thị Dung│ (trống)   ← ROW 5

💡 NULL: Giá trị "không có gì" trong database gọi là NULL (như ô trống trong Excel). Đây là khái niệm quan trọng sẽ gặp rất nhiều về sau!

🔍 Field = Ô (Cell): Giao điểm của 1 Column và 1 Row — giống hệt một cell trong Excel (ít dùng từ này trong thực tế).

Khái Niệm 6: Data Type = Data Validation

📊 Trong Excel, bạn dùng Data Validation để quy định ô chỉ nhận số nguyên hoặc ngày tháng. Database nâng điều này thành bắt buộc và gọi là Data Type.

Bạn muốn cột chứa...Excel (Data Validation)Database (Data Type)
Số nguyên (1, 2, 100...)Validation: Whole numberINTEGER
Số thập phân (99.99)Validation: DecimalNUMERIC(10,2)
Chữ (tên, địa chỉ...)Validation: Text lengthVARCHAR(100)
Ngày thángValidation: DateDATE
Ngày + Giờ*(không có sẵn)*TIMESTAMP
Đúng / SaiValidation: List (Có/Không)BOOLEAN

⚠️ Sự khác biệt lớn: Data Validation Excel có thể bị bỏ qua (copy-paste bỏ qua validation). Data Type trong database là không thể vi phạm — cố nhập chữ vào cột số → database từ chối ngay lập tức!

Khái Niệm 7 & 8: WHERE = Filter, ORDER BY = Sort

🔍 Filter (Excel) = WHERE (SQL)

-- Filter "Phòng ban" = "IT"
SELECT *
FROM nhan_vien
WHERE phong_ban = 'IT';

-- Kết quả:
--  id │  ho_ten     │ phong_ban
--   4 │ Phạm M. Châu│ IT

↕️ Sort (Excel) = ORDER BY (SQL)

-- Sort "Lương" → Lớn đến Nhỏ
SELECT *
FROM nhan_vien
ORDER BY luong DESC;

-- DESC = Giảm dần (Descending)
-- ASC  = Tăng dần  (Ascending)
Thao tác ExcelSQL tương đương
Filter → "Phòng ban" = "IT"WHERE phong_ban = 'IT'
Filter → Lương > 15 triệuWHERE luong > 15000000
Sort → Lương, Lớn → NhỏORDER BY luong DESC
Sort → Tên, A → ZORDER BY ho_ten ASC

Khái Niệm 10 & 11: GROUP BY = Pivot Table

📊 Pivot Table (Excel)

Row Labels: Phòng ban
Values: COUNT, AVERAGE of Lương

 phong_ban  │ count │    avg
────────────┼───────┼────────────

 Kinh doanh │   2   │ 21,000,000

🐘 GROUP BY (SQL)

SELECT
    phong_ban,
    COUNT(*),
    AVG(luong)
FROM nhan_vien
GROUP BY phong_ban;

Khi Nào Nên Chuyển Sang Database?

5 dấu hiệu Excel đã đến giới hạn của nó

Dấu Hiệu 1: Dữ Liệu Quá Lớn

Tình huống: Bộ phận bán hàng cần phân tích lịch sử 3 năm — khoảng 2 triệu dòng giao dịch.

❌ Với Excel

  • File .xlsx giới hạn 1.048.576 hàng — không đủ chứa!
  • Dù chứa được: file nặng vài GB, mở mất 5–10 phút
  • Công thức tính toán cực kỳ chậm
  • Dễ treo máy, mất dữ liệu khi crash

✅ Với Database

  • Không có giới hạn số hàng — hàng triệu, hàng tỷ bản ghi
  • Truy vấn được tối ưu hóa: lọc 2 triệu hàng trong < 1 giây
  • Dữ liệu lưu an toàn trên server, không mất khi máy treo

💡 Ngưỡng thực tế: Khi dữ liệu vượt quá 50.000–100.000 hàng và cần truy vấn thường xuyên, database bắt đầu có ưu thế rõ rệt.

Dấu Hiệu 2: Nhiều Người Cùng Làm Việc

Tình huống: Team 5 người cùng cập nhật danh sách khách hàng trong ngày.

❌ Với Excel

9:00  - An mở file, thêm 20 khách
        → lưu thành "khach_hang_v2.xlsx"
9:30  - Bình (không biết An sửa)
        mở file gốc, sửa 15 địa chỉ
        → lưu đè lên file gốc
10:00 - Ai đúng? File nào mới nhất?
→ Dữ liệu mất, mâu thuẫn, không
  ai tin tưởng file nào!

9:00  - An kết nối, thêm 20 khách
        (lưu ngay lập tức)

        20 khách An vừa thêm,
        sửa 15 địa chỉ (lưu ngay)

        1 nguồn dữ liệu duy nhất
→ Không bao giờ có xung đột!

Dấu Hiệu 3: Cần Đảm Bảo Tính Chính Xác

Tình huống: Báo cáo giới tính nhân viên bị sai vì dữ liệu không nhất quán.

❌ Với Excel

Cột "Giới tính" chứa hỗn hợp:

  • "Nam", "Nữ" ← đúng format
  • "nam", "nữ" ← chữ thường
  • "NAM", "NỮ" ← chữ hoa
  • "M", "F" ← tiếng Anh
  • "1", "0" ← dùng số

=COUNTIF(A:A,"Nữ") → kết quả SAI!

✅ Với Database

-- Khai báo ràng buộc khi tạo bảng:
gioi_tinh VARCHAR(3)
    CHECK (gioi_tinh
        IN ('Nam', 'Nữ'))

✅ Khi ai cố nhập giá trị khác → database từ chối ngay lập tức!

Không bao giờ có "nam", "NAM", "M" lẫn lộn.

Dấu Hiệu 4 & 5: Bảo Mật & Tự Động Hóa

🔐 Dấu hiệu 4: Cần Bảo Mật Theo Cấp Độ

❌ Excel: Ai có file là ai xem được tất cả. Password protect dễ bị bỏ qua khi copy.

✅ Database:

  • ke_toan_truong → xem + sửa tất cả
  • quan_ly_IT → chỉ xem nhân viên IT
  • nhan_vien → không xem bảng lương

⚙️ Dấu hiệu 5: Cần Tự Động Hóa

❌ Excel: Mỗi tuần phải tay tạo báo cáo — export CSV → import → Pivot → format → gửi email. Mất 4 tiếng/tuần.

✅ Database: Dữ liệu cập nhật tự động, báo cáo là 1 câu SQL lưu sẵn, chạy tự động mỗi sáng thứ Hai.

Từ 4 tiếng/tuần → 0 tiếng!

Tóm Tắt: Excel hay Database?

📊 Nên dùng EXCEL khi:

  • ✓ Dữ liệu nhỏ (< 50.000 hàng)
  • ✓ 1–2 người dùng
  • ✓ Phân tích ad-hoc nhanh
  • ✓ Làm báo cáo trực quan, biểu đồ
  • ✓ Dữ liệu cá nhân
  • ✓ Prototype, thử nghiệm nhanh

🐘 Nên dùng DATABASE khi:

  • ✓ Dữ liệu lớn (> 100.000 hàng)
  • ✓ Nhiều người dùng cùng lúc
  • ✓ Cần dữ liệu luôn nhất quán
  • ✓ Cần phân quyền chi tiết
  • ✓ Cần tự động hóa, kết nối app
  • ✓ Hệ thống dài hạn, sản xuất

💡 Sự thật thú vị: Nhiều doanh nghiệp dùng cả hai — database lưu trữ và xử lý dữ liệu, Excel kết nối vào database để làm báo cáo trực quan. Kỹ năng Excel của bạn sẽ vẫn cực kỳ có giá trị!

SQL — Ngôn Ngữ Giao Tiếp Với Database

Structured Query Language — Gần với tiếng Anh hơn bất kỳ ngôn ngữ máy tính nào

SQL Là Gì?

SQL = Structured Query Language — Ngôn ngữ Truy vấn Có Cấu trúc.

Đây là "ngôn ngữ" bạn dùng để nói chuyện với database — giống như công thức Excel là cách bạn "nói chuyện" với Excel.

Python (lập trình phức tạp)

for row in cursor.execute(
    "SELECT * FROM employees"
):
    if row['salary'] > 15000000:
        print(row['name'])

Cần biết lập trình!

SQL (truy vấn đơn giản)

SELECT ho_ten
FROM nhan_vien
WHERE luong > 15000000;

Đọc gần như tiếng Anh tự nhiên! ✅

💡 SQL KHÔNG phải ngôn ngữ lập trình phức tạp như Python hay Java. SQL gần với tiếng Anh thông thường hơn bất kỳ ngôn ngữ máy tính nào khác.

Quy Tắc Cơ Bản Của SQL

1. Kết thúc bằng dấu chấm phẩy ;

SELECT * FROM nhan_vien;  ← đúng
SELECT * FROM nhan_vien   ← thiếu ;

2. Không phân biệt HOA / thường

SELECT * FROM nhan_vien;
select * from nhan_vien;
Select * From Nhan_Vien;
-- Ba câu trên giống hệt nhau!

3. Quy ước: Keyword viết HOA

SELECT ho_ten
FROM nhan_vien
WHERE luong > 15000000;
-- SELECT, FROM, WHERE → HOA (keyword)
-- ho_ten, nhan_vien  → thường (tên bảng)

4. Comment bắt đầu bằng --

-- Đây là ghi chú, SQL bỏ qua
SELECT * FROM nhan_vien;
-- Ghi chú cuối dòng cũng được

Đọc SQL Như Tiếng Anh

Điều thú vị nhất về SQL — hãy đọc như tiếng Anh tự nhiên:

Câu SQLĐọc bằng tiếng AnhÝ nghĩa tiếng Việt
SELECT * FROM nhan_vien Select all from employees Lấy tất cả từ bảng nhân viên
SELECT ho_ten, luong FROM nhan_vien Select name, salary from employees Lấy tên và lương từ bảng nhân viên
SELECT * FROM nhan_vien WHERE phong_ban = 'IT' Select all from employees where department is IT Lấy tất cả nhân viên phòng IT
SELECT * FROM nhan_vien WHERE luong > 15000000 Select all where salary exceeds 15M Nhân viên có lương trên 15 triệu
SELECT ho_ten FROM nhan_vien ORDER BY luong DESC Select name, order by salary descending Tên nhân viên, sắp theo lương giảm dần
SELECT COUNT(*) FROM nhan_vien Count all from employees Đếm tổng số nhân viên
