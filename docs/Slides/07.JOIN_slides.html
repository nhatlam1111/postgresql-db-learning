7.2

Giải Pháp: Tách Bảng & Liên Kết

Mỗi thông tin chỉ lưu MỘT lần — dùng mã số để nối lại

🔑 Primary Key & Foreign Key

Database tách dữ liệu lặp thành 2 bảng riêng, nối bằng mã số:

khach_hang
id ← PK
ho_ten
dien_thoai
1 ──────< N
don_hang
id
khach_hang_id ← FK
ngay_dat, tong_tien

🔑 Primary Key (Khóa chính)

Cột định danh duy nhất cho mỗi hàng. Không NULL, không trùng.

🔗 Foreign Key (Khóa ngoại)

Cột tham chiếu đến PK bảng khác — là "cầu nối" giữa hai bảng.

📊 Excel: PK giống cột Mã KH duy nhất. FK giống cột tra cứu trong VLOOKUP.

7.3

INNER JOIN

Lấy dữ liệu có ở CẢ HAI bảng — như VLOOKUP chỉ lấy hàng khớp

📝 Cú Pháp INNER JOIN

A
A∩B
B

Chỉ lấy phần giao nhau — hàng có khớp ở cả hai bảng

SELECT  bang1.cot, bang2.cot
FROM    bang1
INNER JOIN bang2
    ON bang1.khoa_ngoai = bang2.khoa_chinh;

-- Có thể viết ngắn (bỏ INNER):
JOIN bang2 ON bang1.col = bang2.col

📊 Excel: VLOOKUP chỉ trả kết quả khi tìm thấy — INNER JOIN hoạt động giống vậy.

💻 Ví Dụ: Đơn Hàng + Tên Khách

-- Hiển thị đơn hàng kèm thông tin khách hàng
SELECT
    dh.ma_don_hang,
    kh.ho_ten           AS ten_khach,
    kh.dien_thoai,
    dh.ngay_dat,
    dh.tong_tien
FROM don_hang dh
INNER JOIN khach_hang kh ON dh.khach_hang_id = kh.id
ORDER BY dh.ngay_dat DESC;
Kết quả: ┌─────────────┬──────────────────┬────────────┬────────────┬───────────┐ │ ma_don_hang │ ten_khach │ dien_thoai │ ngay_dat │ tong_tien │ ├─────────────┼──────────────────┼────────────┼────────────┼───────────┤ │ DH012 │ Nguyễn Văn An │ 0912234567 │ 2024-04-18 │ 11000000 │ │ DH011 │ Trần Thị Mai │ 0901123456 │ 2024-04-10 │ 28000000 │ └─────────────┴──────────────────┴────────────┴────────────┴───────────┘

✍️ Table Alias — Viết Gọn Tên Bảng

❌ Không alias (dài)

FROM don_hang
JOIN khach_hang
  ON don_hang.khach_hang_id
    = khach_hang.id
SELECT don_hang.ma_don,
  khach_hang.ho_ten

✅ Có alias (ngắn gọn)

FROM don_hang dh
JOIN khach_hang kh
  ON dh.khach_hang_id
    = kh.id
SELECT dh.ma_don,
  kh.ho_ten

💡 Quy ước: Dùng 2-3 chữ cái đầu — don_hang → dh, khach_hang → kh, nhan_vien → nv

⚠️ Bắt buộc viết bang.cot khi JOIN — vì nhiều bảng có cùng tên cột (ví dụ id). Nếu không → lỗi "ambiguous".

7.4

LEFT JOIN

Lấy TẤT CẢ từ bảng trái — dù không khớp cũng giữ lại

📝 LEFT JOIN — Lấy Tất Cả Từ Bảng Trái

A
A∩B
B

Lấy toàn bộ A + phần khớp của B. Không khớp → NULL

SELECT kh.ho_ten, dh.ma_don_hang, dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id;
Kết quả: ┌──────────────────┬─────────────┬───────────┐ │ ho_ten │ ma_don_hang │ tong_tien │ ├──────────────────┼─────────────┼───────────┤ │ Trần Thị Mai │ DH001 │ 500000 │ │ Trần Thị Mai │ DH003 │ 800000 │ │ Nguyễn Văn An │ DH002 │ 300000 │ │ Lê Thị Bình │ NULL │ NULL │ ← chưa có đơn! └──────────────────┴─────────────┴───────────┘

📊 Excel: LEFT JOIN giống =IFERROR(VLOOKUP(...), "Không tìm thấy") — hàng không khớp vẫn hiện, nhưng với NULL.

🔍 Tìm Hàng "Mồ Côi" — LEFT JOIN + IS NULL

Thủ thuật hay: tìm những hàng ở bảng trái không có ở bảng phải:

-- Tìm khách hàng CHƯA CÓ đơn hàng nào
SELECT kh.ho_ten, kh.dien_thoai
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
WHERE dh.id IS NULL;
-- Nếu không khớp → tất cả cột bảng phải = NULL (kể cả dh.id)
khach_hang (tất cả)
LEFT JOIN
don_hang
WHERE dh.id IS NULL
Khách chưa mua

💡 Đây là pattern cực kỳ phổ biến — dùng để tìm khách chưa mua, sản phẩm chưa bán, nhân viên chưa có đơn...

7.5

RIGHT JOIN & FULL JOIN

Hai loại JOIN bổ sung — ít dùng hơn nhưng cần biết

➡️ RIGHT JOIN — Ngược LEFT JOIN

A
∩
B

Lấy tất cả bảng phải — NULL nếu bảng trái không khớp.

-- RIGHT JOIN (ít dùng)
SELECT kh.ho_ten, dh.ma_don_hang
FROM khach_hang kh
RIGHT JOIN don_hang dh ON kh.id = dh.khach_hang_id;

💡 Mẹo: Ít dùng RIGHT JOIN — viết lại thành LEFT JOIN bằng cách đổi thứ tự bảng. Dễ đọc hơn!

↔️ FULL JOIN — Tất Cả Từ Cả Hai

A
∩
B

Lấy tất cả từ cả hai bảng — NULL ở bên nào không khớp.

-- FULL JOIN — bức tranh toàn cảnh
SELECT kh.ho_ten, dh.ma_don_hang
FROM khach_hang kh
FULL JOIN don_hang dh ON kh.id = dh.khach_hang_id;

📊 Excel: FULL JOIN giống merge 2 bảng giữ tất cả — hàng không khớp vẫn hiện với ô trống.

7.6

Tổng Hợp 4 Loại JOIN

Bức tranh toàn cảnh — khi nào dùng loại nào?

🗺️ Bản Đồ 4 Loại JOIN

Loại JOINLấy gì?NULL khi?Khi nào dùng?
INNER JOIN Hàng khớp ở cả hai Không có NULL Cần dữ liệu đầy đủ
LEFT JOIN Tất cả bảng trái + khớp bảng phải Cột bảng phải = NULL Giữ tất cả bảng chính
RIGHT JOIN Khớp bảng trái + tất cả bảng phải Cột bảng trái = NULL Dùng LEFT thay thế
FULL JOIN Tất cả từ cả hai Cả hai phía Bức tranh toàn cảnh

💡 Thực tế: 90% trường hợp bạn chỉ cần INNER JOIN và LEFT JOIN. Thành thạo hai loại này là đủ cho hầu hết công việc.

7.7

JOIN Nhiều Bảng

Kết nối 3, 4 bảng cùng lúc — VLOOKUP lồng nhau phiên bản SQL

🔗 Ví Dụ: JOIN 4 Bảng

khach_hang
id
──<
don_hang
khach_hang_id
id

chi_tiet_don_hang
don_hang_id

>──

id
SELECT
    kh.ho_ten, dh.ma_don_hang, sp.ten_san_pham,
    ct.so_luong, ct.don_gia,
    ct.so_luong * ct.don_gia AS thanh_tien
FROM chi_tiet_don_hang ct
JOIN don_hang dh   ON ct.don_hang_id = dh.id
JOIN khach_hang kh ON dh.khach_hang_id = kh.id
JOIN san_pham sp   ON ct.san_pham_id = sp.id
ORDER BY dh.ngay_dat DESC;

💡 Mẹo đọc: Đọc từ bảng trung tâm ra ngoài. chi_tiet_don_hang là trung tâm — nối ra 3 bảng xung quanh.

7.8

JOIN + GROUP BY

Combo mạnh nhất — tạo báo cáo từ nhiều bảng

🏆 Ví Dụ: Top Khách Hàng

-- Tổng chi tiêu của mỗi khách hàng
SELECT
    kh.ho_ten,
    kh.dien_thoai,
    COUNT(dh.id)            AS so_don_hang,
    SUM(dh.tong_tien)       AS tong_chi_tieu
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
    AND dh.trang_thai = 'hoan_thanh'
GROUP BY kh.id, kh.ho_ten, kh.dien_thoai
ORDER BY tong_chi_tieu DESC NULLS LAST;

📊 Excel: Giống tạo Pivot Table từ nhiều sheet — GROUP BY gom nhóm, SUM tính tổng, JOIN kết nối dữ liệu.

📦 Ví Dụ: Top Sản Phẩm Bán Chạy

-- Top 5 sản phẩm bán chạy nhất (theo số lượng)
SELECT
    sp.ten_san_pham,
    SUM(ct.so_luong)                AS tong_ban,
    SUM(ct.so_luong * ct.don_gia)   AS doanh_thu
FROM san_pham sp
JOIN chi_tiet_don_hang ct ON sp.id = ct.san_pham_id
JOIN don_hang dh          ON ct.don_hang_id = dh.id
WHERE dh.trang_thai = 'hoan_thanh'
GROUP BY sp.id, sp.ten_san_pham
ORDER BY tong_ban DESC
LIMIT 5;

💡 Pattern: JOIN nhiều bảng → WHERE lọc → GROUP BY gom → ORDER BY + LIMIT lấy top. Đây là combo tạo báo cáo phổ biến nhất!

⚖️ Điều Kiện Trong ON vs WHERE

Khi dùng LEFT JOIN, vị trí điều kiện ảnh hưởng kết quả:

✅ Điều kiện trong ON
FROM khach_hang kh
LEFT JOIN don_hang dh
  ON kh.id = dh.khach_hang_id
  AND dh.trang_thai = 'hoan_thanh'
-- Lọc TRƯỚC join
-- Khách không đơn → vẫn hiện
❌ Điều kiện trong WHERE
FROM khach_hang kh
LEFT JOIN don_hang dh
  ON kh.id = dh.khach_hang_id
WHERE dh.trang_thai = 'hoan_thanh'
-- Lọc SAU join
-- Khách không đơn → bị loại!

⚠️ CẢNH BÁO: WHERE trên cột bảng phải sẽ vô tình biến LEFT JOIN thành INNER JOIN — vì NULL bị loại bởi WHERE!

7.9

Những Lỗi Hay Gặp

4 lỗi phổ biến khi dùng JOIN — biết trước để tránh

💥 Lỗi 1: Quên ON — Cartesian Product

❌ NGUY HIỂM — quên ON
SELECT kh.ho_ten, dh.ma_don_hang
FROM khach_hang kh
JOIN don_hang dh;
-- 100 khách × 200 đơn = 20,000 hàng!
✅ ĐÚNG — luôn có ON
SELECT kh.ho_ten, dh.ma_don_hang
FROM khach_hang kh
JOIN don_hang dh
  ON kh.id = dh.khach_hang_id;

⚠️ Dấu hiệu: Kết quả bất thường nhiều hàng → kiểm tra lại điều kiện ON ngay!

🔤 Lỗi 2: Tên Cột Mơ Hồ (Ambiguous)

❌ LỖI — cả hai bảng đều có "id"
SELECT id, ho_ten, tong_tien
FROM khach_hang kh
JOIN don_hang dh
  ON kh.id = dh.khach_hang_id;
-- ERROR: column "id" is ambiguous
✅ ĐÚNG — chỉ rõ bảng
SELECT kh.id, kh.ho_ten,
       dh.tong_tien
FROM khach_hang kh
JOIN don_hang dh
  ON kh.id = dh.khach_hang_id;

🚫 Lỗi 3: WHERE Biến LEFT JOIN → INNER JOIN

❌ SAI — WHERE loại hàng NULL
SELECT kh.ho_ten, dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh
  ON kh.id = dh.khach_hang_id
WHERE dh.trang_thai = 'hoan_thanh';
-- NULL bị loại → mất khách chưa mua!
✅ ĐÚNG — đặt trong ON
SELECT kh.ho_ten, dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh
  ON kh.id = dh.khach_hang_id
  AND dh.trang_thai = 'hoan_thanh';

🎯 Lỗi 4: JOIN Sai Cột — Kết Quả Sai Âm Thầm

❌ SAI — JOIN nhầm cột
JOIN don_hang dh
  ON kh.id = dh.id
-- JOIN id với id thay vì khach_hang_id
-- Query chạy được nhưng KẾT QUẢ SAI!
✅ ĐÚNG — FK → PK
JOIN don_hang dh
  ON kh.id = dh.khach_hang_id
-- Nối khóa ngoại với khóa chính
-- Logic đúng!

⚠️ CẢNH BÁO: Lỗi nguy hiểm nhất — query chạy không báo lỗi, kết quả trông hợp lý nhưng sai hoàn toàn. Luôn kiểm tra logic ON!

⚙️ Thứ Tự Thực Thi Với JOIN

JOIN được xử lý ngay sau FROM, trước tất cả mệnh đề khác:

📝 Thứ tự VIẾT

  1. SELECT
  2. FROM
  3. JOIN ... ON
  4. WHERE
  5. GROUP BY
  6. HAVING
  7. ORDER BY
  8. LIMIT

⚙️ Thứ tự THỰC THI

  1. FROM bang
  2. JOIN bang2 ON ...
  3. WHERE dk
  4. GROUP BY cot
  5. HAVING dk
  6. SELECT cot
  7. ORDER BY cot
  8. LIMIT n

💡 Hệ quả: Alias bảng (FROM/JOIN) dùng được ngay trong ON. Alias cột (SELECT) chỉ dùng trong ORDER BY.
