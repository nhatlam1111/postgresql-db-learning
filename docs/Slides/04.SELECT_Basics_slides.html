4.1

SELECT — Câu Lệnh Quan Trọng Nhất

Đọc dữ liệu từ bảng — cú pháp cơ bản

SELECT * và SELECT Cột Cụ Thể

SELECT * — Lấy tất cả cột

-- Xem toàn bộ bảng
-- Như mở sheet, nhìn toàn bộ
SELECT * FROM nhan_vien;

Dấu * = "lấy tất cả cột"

⚠️ Tránh dùng SELECT * trong thực tế — lấy thừa dữ liệu → chậm hơn, code dễ lỗi khi cấu trúc bảng thay đổi.

SELECT cột cụ thể

-- Chỉ xem 3 cột cần thiết
-- Như ẩn cột trong Excel
SELECT ho_ten, luong, phong_ban
FROM nhan_vien;

Kết quả:

 ho_ten         | luong    | phong_ban
 Trần Thị Mai   | 15000000 | Kế toán
 Nguyễn Văn An  | 20000000 | Kinh doanh
 Lê Thị Bình    | 18000000 | Nhân sự

📊 Thứ tự cột: Trong SELECT bạn có thể đổi thứ tự cột tùy ý — giống như kéo cột sang trái/phải trong Excel. SELECT phong_ban, ho_ten hoàn toàn hợp lệ dù trong bảng ho_ten đứng trước.

Cú Pháp SELECT Đầy Đủ

Phần tối thiểu bắt buộc: SELECT ... FROM ... — các phần còn lại là tùy chọn.

SELECT  [DISTINCT]  cot1, cot2, cot3, ...   ← Tuần 4 ✅
FROM    ten_bang                              ← Tuần 4 ✅
[WHERE     dieu_kien]                         ← Lọc hàng       (Tuần 5)
[GROUP BY  cot_nhom]                          ← Nhóm dữ liệu   (Tuần 6)
[HAVING    dieu_kien_nhom]                    ← Lọc nhóm       (Tuần 6)
[ORDER BY  cot [ASC|DESC]]                  ← Sắp xếp        (Tuần 5)
[LIMIT  n  OFFSET  m]                        ← Phân trang     (Tuần 4 ✅)

Câu SQL tối giản

SELECT *
FROM nhan_vien;

Hợp lệ 100%

Câu SQL đầy đủ

SELECT DISTINCT phong_ban,
    ROUND(AVG(luong),0) AS tb
FROM nhan_vien
WHERE ngay_vao > '2022-01-01'
GROUP BY phong_ban
HAVING AVG(luong) > 15000000
ORDER BY tb DESC
LIMIT 3;

Thứ Tự Viết ≠ Thứ Tự Thực Thi

SQL có thứ tự từ khóa cố định khi viết, nhưng PostgreSQL thực thi theo thứ tự hoàn toàn khác:

📝 Thứ tự VIẾT (bạn gõ)

  1. SELECT [DISTINCT]
  2. FROM
  3. WHERE
  4. GROUP BY
  5. HAVING
  6. ORDER BY
  7. LIMIT / OFFSET

⚙️ Thứ tự THỰC THI (PostgreSQL xử lý)

  1. FROM (xác định bảng)
  2. WHERE (lọc hàng)
  3. GROUP BY
  4. HAVING
  5. SELECT ← bước 5!
  6. ORDER BY
  7. LIMIT / OFFSET

⚠️ Hệ quả quan trọng: WHERE chạy ở bước 2, còn SELECT chạy ở bước 5 → trong WHERE, bạn KHÔNG dùng được alias đã đặt trong SELECT. (Chi tiết ở slide 4.8)

4.2

AS — Đặt Tên Hiển Thị

Alias — đặt tên mới cho cột trong kết quả truy vấn

AS — Alias Là Gì?

📊 Trong Excel: khi làm báo cáo bạn gõ vào hàng đầu: "Họ và Tên", "Mức Lương (VNĐ)", "Phòng Ban" thay vì giữ nguyên ho_ten, luong, phong_ban.
Trong SQL, AS làm điều y chang — tên thật của cột trong bảng không thay đổi.

-- Alias đơn giản
SELECT
    ho_ten      AS "Họ và tên",
    luong       AS "Mức lương (VNĐ)",
    phong_ban   AS "Phòng ban"
FROM nhan_vien;

Kết quả:

 Họ và tên       | Mức lương (VNĐ) | Phòng ban
 Trần Thị Mai    |        15000000 | Kế toán
 Nguyễn Văn An   |        20000000 | Kinh doanh

💡 Alias tồn tại chỉ trong kết quả truy vấn — bảng gốc không bị ảnh hưởng.

Quy Tắc Đặt Alias

Tình huốngCú phápVí dụ
Có khoảng trắng hoặc dấu tiếng ViệtDùng nháy kép "..."AS "Họ và tên"
Chỉ chữ thường, số, gạch dướiCó thể bỏ nháy képAS tong_luong
Muốn giữ nguyên chữ HoaDùng nháy kép "..."AS "TongLuong"

⚠️ Cảnh Báo: Nháy Đơn vs Nháy Kép

-- ✅ ĐÚNG: alias dùng nháy kép, giá trị dùng nháy đơn
SELECT ho_ten AS "Họ tên"
FROM nhan_vien
WHERE phong_ban = 'Kế toán';

-- ❌ SAI: alias không dùng nháy đơn
SELECT ho_ten AS 'Họ tên'  ← Lỗi!

AS Với Tính Toán & Table Alias

Alias cho cột tính toán

SELECT
    ho_ten,
    luong             AS "Lương trước thuế",
    ROUND(luong*0.10,0) AS "Thuế TNCN (10%)",
    ROUND(luong*0.90,0) AS "Lương sau thuế"
FROM nhan_vien;

Alias làm cho cột tính toán trở nên dễ đọc trong báo cáo.

Table Alias (Alias bảng)

-- "nv" là alias cho bảng nhan_vien
SELECT nv.ho_ten, nv.luong
FROM nhan_vien AS nv;

-- Cách viết tắt (bỏ AS cũng được)
SELECT nv.ho_ten, nv.luong
FROM nhan_vien nv;

💡 Hiện tại với 1 bảng, alias bảng chưa cần thiết. Sẽ rất quan trọng khi học JOIN ở Tuần 7!

4.3

Biểu Thức Tính Toán

Tính toán trong SELECT — như công thức Excel trong ô

Toán Tử Số Học

Toán tửÝ nghĩaVí dụ SQLExcel tương đương
+Cộngluong + 5000000=B2+5000000
-Trừluong - 2000000=B2-2000000
*Nhângia * so_luong=C2*D2

-- Tính lương tháng → lương tuần → lương ngày
SELECT
    ho_ten,
    luong                            AS "Lương tháng",
    ROUND(luong / 4.33, 0)           AS "Lương tuần",
    ROUND(luong / 26, 0)             AS "Lương ngày (26 ngày công)"
FROM nhan_vien;

⚠️ Bẫy: Chia Số Nguyên

⚠️ CẢNH BÁO: Chia số nguyên cho số nguyên → kết quả là số nguyên (phần thập phân bị cắt!)

❌ Kết quả SAI

SELECT 7 / 2;    ← Kết quả: 3 (không phải 3.5!)
SELECT 10 / 3;   ← Kết quả: 3 (không phải 3.33...)

-- Nguy hiểm thực tế:
SELECT luong / 12 FROM nhan_vien;
-- Nếu luong là INTEGER → kết quả bị cắt!

✅ Cách Sửa

-- Cách 1: Dùng số thập phân
SELECT 7.0 / 2;          ← 3.5 ✅

-- Cách 2: Ép kiểu (type cast)
SELECT 7::NUMERIC / 2;  ← 3.5 ✅
SELECT CAST(7 AS NUMERIC) / 2;  ← 3.5 ✅

-- Ví dụ thực tế an toàn:
SELECT luong / 12.0 FROM nhan_vien; ✅
SELECT luong::NUMERIC / 12 FROM nhan_vien; ✅

📊 So sánh Excel: Excel không có vấn đề này — mọi phép chia đều cho kết quả thập phân tự động. SQL nghiêm ngặt hơn về kiểu dữ liệu!

SELECT
    ROUND(15567890.5, 0)   AS "Làm tròn nguyên",  -- 15567891
    ROUND(15567890.5, -3)  AS "Làm tròn nghìn",   -- 15568000
    CEIL(15.001)            AS "Làm tròn lên",     -- 16
    FLOOR(15.999)           AS "Làm tròn xuống",   -- 15
    TRUNC(15.999, 0)        AS "Cắt thẳng";        -- 15

Ví Dụ Thực Tế: Báo Cáo Lương

📊 Tương đương Excel: Đây chính xác là điều bạn làm với nhiều cột công thức trong Excel — SQL làm được y chang nhưng nhanh hơn nhiều với triệu hàng!

-- Báo cáo lương với các khoản bảo hiểm
SELECT
    ho_ten                                    AS "Họ và tên",
    phong_ban                                 AS "Phòng ban",
    luong                                     AS "Lương gross",
    ROUND(luong * 0.08, 0)                   AS "BHXH (8%)",
    ROUND(luong * 0.015, 0)                  AS "BHYT (1.5%)",
    ROUND(luong * 0.01, 0)                   AS "BHTN (1%)",
    ROUND(luong * 0.105, 0)                  AS "Tổng BH (10.5%)",
    ROUND(luong - luong * 0.105, 0)          AS "Thu nhập chịu thuế",
    ROUND((luong - luong * 0.105) * 0.10, 0) AS "Thuế TNCN (~10%)"
FROM nhan_vien;
4.4

DISTINCT — Loại Bỏ Giá Trị Trùng

Tương đương Remove Duplicates trong Excel

DISTINCT Cơ Bản

Bảng nhan_vien có 6 nhân viên, 4 phòng ban. Câu hỏi: "Có những phòng ban nào?"

❌ Không có DISTINCT

SELECT phong_ban
FROM nhan_vien;

Kết quả: Kế toán, Kinh doanh, Nhân sự, IT, Kế toán, Kinh doanh

6 hàng — bị trùng! ❌

✅ Có DISTINCT

SELECT DISTINCT phong_ban
FROM nhan_vien;

Kết quả: Kế toán, Kinh doanh, Nhân sự, IT

4 hàng — không trùng! ✅

📊 Tương đương Excel: Data tab → Remove Duplicates → chọn cột cần loại trùng. SQL làm điều tương tự mà không thay đổi dữ liệu gốc.

DISTINCT Nhiều Cột & COUNT(DISTINCT)

DISTINCT trên nhiều cột

-- Tổ hợp (phong_ban, chuc_vu) duy nhất
SELECT DISTINCT phong_ban, chuc_vu
FROM nhan_vien;

💡 Không phải "phòng ban duy nhất" + "chức vụ duy nhất", mà là cặp (phong_ban, chuc_vu) duy nhất.

📊 Excel: Remove Duplicates → tích chọn cả hai cột cùng lúc.

COUNT(DISTINCT ...) — Đếm giá trị khác nhau

-- Có bao nhiêu phòng ban?
SELECT COUNT(DISTINCT phong_ban)
    AS "Số phòng ban"
FROM nhan_vien;
-- Kết quả: 4

-- Có bao nhiêu danh mục sản phẩm?
SELECT COUNT(DISTINCT danh_muc)
    AS "Số danh mục"
FROM san_pham;

📊 Excel: =SUMPRODUCT(1/COUNTIF(A2:A100,A2:A100)) — công thức phức tạp! SQL đơn giản hơn nhiều.

4.5

Hàm Xử Lý Chuỗi

UPPER · LOWER · TRIM · LEFT · SUBSTRING · CONCAT…

Nối Chuỗi: || và CONCAT()

Toán tử || (pipe pipe)

-- Nối họ tên với phòng ban
SELECT
    ho_ten || ' - ' || phong_ban
    AS "Thông tin nhân viên"
FROM nhan_vien;
-- Trần Thị Mai - Kế toán
-- Nguyễn Văn An - Kinh doanh

📊 Excel: =A2 & " - " & F2

⚠️ Bẫy: || với NULL

-- Nếu email là NULL:
SELECT 'Email: ' || email FROM nhan_vien;
-- Người không có email → NULL!
-- (mất cả phần "Email: ")

CONCAT() — An toàn hơn với NULL

-- CONCAT() bỏ qua NULL
SELECT
    'Email: ' || COALESCE(email, 'Chưa có')
FROM nhan_vien;
-- "Email: Chưa có" khi email = NULL
Tình huống|| kết quảCONCAT() kết quả
Mọi cột có giá trị'A - B''A - B'
Một cột là NULLNULL'A - ' (bỏ qua NULL)

Ví Dụ Thực Tế: Xử Lý Chuỗi

-- Chuẩn hóa email: chữ thường + xóa khoảng trắng
SELECT
    ho_ten,
    LOWER(TRIM(email))       AS "Email chuẩn hóa",
    LENGTH(email)            AS "Độ dài email"
FROM nhan_vien;

-- Tạo username từ email (lấy phần trước @)
SELECT
    ho_ten,
    email,
    SPLIT_PART(email, '@', 1)  AS "Username"
FROM nhan_vien;

-- Mã nhân viên dạng NV-001, NV-002...
SELECT
    'NV-' || LPAD(id::TEXT, 3, '0')  AS "Mã NV",
    ho_ten
FROM nhan_vien;
-- Kết quả: NV-001, NV-002, NV-003...

-- Kiểm tra email hợp lệ (có chứa @)
SELECT
    ho_ten,
    email,
    POSITION('@' IN email) > 0  AS "Có @ không?"
FROM nhan_vien;

SELECT
    ROUND(MIN(luong), 0)    AS "Lương thấp nhất",
    ROUND(MAX(luong), 0)    AS "Lương cao nhất",
    ROUND(AVG(luong), 0)    AS "Lương trung bình",

SELECT

FROM nhan_vien;

SELECT
    ho_ten,
    luong,
    MOD(luong, 12) AS "Phần dư khi chia 12"
FROM nhan_vien;
4.7

LIMIT & OFFSET

Xem một phần dữ liệu — Phân trang

LIMIT — Giới Hạn Số Hàng

📊 Tương đương Excel: Giống như bạn kéo xuống đến hàng thứ 10 để xem sơ qua — thay vì phải nhìn toàn bộ 200.000 hàng.

-- Chỉ lấy 5 hàng đầu
SELECT * FROM nhan_vien LIMIT 5;

-- Preview 10 sản phẩm đầu
SELECT ten_sp, gia
FROM san_pham LIMIT 10;

-- 3 sản phẩm đắt nhất
SELECT ten_sp, gia
FROM san_pham
ORDER BY gia DESC
LIMIT 3;

⚠️ Không có ORDER BY → thứ tự không đảm bảo!

Nếu không có ORDER BY, PostgreSQL có thể trả về bất kỳ hàng nào — không nhất thiết là hàng bạn INSERT vào đầu tiên.

✅ Cách đúng

-- Luôn kết hợp LIMIT với ORDER BY
SELECT * FROM san_pham
ORDER BY id LIMIT 5;

SELECT * FROM san_pham
ORDER BY gia DESC LIMIT 5;

OFFSET — Phân Trang Dữ Liệu

OFFSET kết hợp với LIMIT cho phép phân trang — các trang web hiển thị danh sách sản phẩm (trang 1, 2, 3...) đều dùng kỹ thuật này!

-- Trang 1: Hàng 1–10
SELECT * FROM san_pham
LIMIT 10 OFFSET 0;

-- Trang 2: Hàng 11–20
SELECT * FROM san_pham
LIMIT 10 OFFSET 10;

-- Trang 3: Hàng 21–30
SELECT * FROM san_pham
LIMIT 10 OFFSET 20;

💡 Công thức tính OFFSET

OFFSET = (số_trang - 1) × số_hàng_mỗi_trang

EXTRACT & AGE — Trích Xuất Thành Phần Ngày

EXTRACT — Lấy thành phần

EXTRACT(YEAR    FROM ngay_sinh)  -- 1995
EXTRACT(MONTH   FROM ngay_sinh)  -- 3
EXTRACT(DAY     FROM ngay_sinh)  -- 20
EXTRACT(HOUR    FROM thoi_gian)  -- 14
EXTRACT(MINUTE  FROM thoi_gian)  -- 30
EXTRACT(DOW     FROM ngay_sinh)  -- 0=CN...6=T7
EXTRACT(WEEK    FROM ngay_sinh)  -- Tuần 1-53
EXTRACT(QUARTER FROM ngay_sinh)  -- Quý 1-4

AGE — Tính tuổi

-- Tính tuổi nhân viên
SELECT
    ho_ten,
    ngay_sinh,
    AGE(ngay_sinh)              AS "Tuổi đầy đủ",
    EXTRACT(YEAR FROM
        AGE(ngay_sinh))           AS "Số tuổi"
FROM nhan_vien;

Kết quả "Tuổi đầy đủ":
30 years 1 mon 25 days
Kết quả "Số tuổi": 30 ← dễ dùng hơn!

TO_CHAR — Format Ngày Theo Ý Muốn

Các format hay dùng

TO_CHAR(ngay_sinh, 'DD/MM/YYYY')
-- 20/03/1995
TO_CHAR(ngay_sinh, 'YYYY-MM-DD')
-- 1995-03-20  (chuẩn ISO)
TO_CHAR(ngay_sinh, 'DD "tháng" MM "năm" YYYY')
-- 20 tháng 03 năm 1995
TO_CHAR(now(), 'HH24:MI:SS')
-- 14:30:25  (giờ 24h)

📊 Excel: =TEXT(A1,"DD/MM/YYYY")

Ví dụ tổng hợp

SELECT
    ho_ten                     AS "Họ và tên",
    TO_CHAR(ngay_sinh,
        'DD/MM/YYYY')          AS "Ngày sinh",
    EXTRACT(YEAR FROM
        AGE(ngay_sinh))          AS "Tuổi",
    EXTRACT(YEAR FROM
        AGE(ngay_vao))           AS "Năm làm việc",
    CURRENT_DATE - ngay_vao    AS "Số ngày đã làm"
FROM nhan_vien;
