## 9.1 UPDATE — Sửa Dữ Liệu

### So Sánh Với Excel

Trong Excel, khi muốn sửa dữ liệu bạn chỉ cần click vào ô và gõ lại. Trong SQL, bạn dùng lệnh `UPDATE`:

```
Excel:                              SQL:
Mở file → Click ô → Sửa → Save     UPDATE bang SET cot = gia_tri WHERE dieu_kien;
```

Điểm khác biệt quan trọng: SQL có thể **sửa hàng trăm nghìn hàng cùng một lúc** — đây là sức mạnh, nhưng cũng là con dao hai lưỡi.

### Cú Pháp

```sql
UPDATE ten_bang
SET
    cot_1 = gia_tri_moi_1,
    cot_2 = gia_tri_moi_2,
    ...
WHERE dieu_kien;    -- ← LUÔN CÓ WHERE (trừ khi cố ý sửa tất cả)
```

### Các Trường Hợp Thực Tế

**Sửa một hàng cụ thể theo ID:**

```sql
-- Sửa lương nhân viên có id = 5
UPDATE nhan_vien
SET luong = 16000000
WHERE id = 5;
```

**Sửa nhiều cột cùng lúc:**

```sql
-- Cập nhật email và nickname của nhân viên id = 1
UPDATE nhan_vien
SET
    email    = 'mai.tran.new@email.com',
    nickname = 'Mai'
WHERE id = 1;
```

**Sửa dựa trên giá trị hiện tại (tăng/giảm %):**

```sql
-- Tăng lương 10% cho toàn bộ phòng IT
UPDATE nhan_vien
SET luong = luong * 1.10
WHERE phong_ban = 'IT';
```

```
Trước:                              Sau:
┌────┬──────────────┬──────────┐   ┌────┬──────────────┬──────────┐
│ id │ ho_ten       │ luong    │   │ id │ ho_ten       │ luong    │
├────┼──────────────┼──────────┤   ├────┼──────────────┼──────────┤
│  4 │ Phạm M. Châu │ 25000000 │   │  4 │ Phạm M. Châu │ 27500000 │ ← +10%
│  9 │ Lê Văn Dũng  │ 20000000 │   │  9 │ Lê Văn Dũng  │ 22000000 │ ← +10%
│ 10 │ Đặng Thị Lan │ 19000000 │   │ 10 │ Đặng Thị Lan │ 20900000 │ ← +10%
└────┴──────────────┴──────────┘   └────┴──────────────┴──────────┘
```

**Sửa dùng CASE WHEN (sửa khác nhau theo điều kiện):**

```sql
-- Mỗi phòng ban được tăng lương theo mức khác nhau
UPDATE nhan_vien
SET luong = luong * CASE phong_ban
    WHEN 'IT'         THEN 1.15   -- IT: +15%
    WHEN 'Kinh doanh' THEN 1.10   -- Kinh doanh: +10%
    WHEN 'Kế toán'    THEN 1.08   -- Kế toán: +8%
    ELSE                   1.05   -- Còn lại: +5%
END
WHERE tinh_trang = 'dang_lam';    -- chỉ nhân viên đang làm
```

### UPDATE Với Subquery

```sql
-- Cập nhật trạng thái đơn hàng thành 'qua_han'
-- cho những đơn 'cho_xu_ly' đã quá 30 ngày
UPDATE don_hang
SET trang_thai = 'qua_han'
WHERE trang_thai = 'cho_xu_ly'
  AND ngay_dat < CURRENT_DATE - INTERVAL '30 days';
```

> ⚠️ **CẢNH BÁO — Lỗi phổ biến nhất với UPDATE:**
>
> ```sql
> -- ❌ NGUY HIỂM: Quên WHERE → SỬA TẤT CẢ hàng trong bảng!
> UPDATE nhan_vien
> SET luong = 5000000;   -- Toàn bộ 12 nhân viên bị đổi lương về 5 triệu!
>
> -- ✅ AN TOÀN: Luôn có WHERE
> UPDATE nhan_vien
> SET luong = 5000000
> WHERE id = 99;  -- Chỉ nhân viên id=99
> ```
>
> Không có lệnh Ctrl+Z sau UPDATE (trừ khi dùng Transaction — xem phần 9.5).

## 9.2 DELETE — Xóa Dữ Liệu

### So Sánh Với Excel

Trong Excel bạn chọn hàng → chuột phải → Delete Row. Trong SQL:

```sql
DELETE FROM ten_bang
WHERE dieu_kien;    -- ← LUÔN CÓ WHERE
```

### Các Trường Hợp Thực Tế

**Xóa một hàng theo ID:**

```sql
-- Xóa nhân viên có id = 12
DELETE FROM nhan_vien
WHERE id = 12;
```

**Xóa theo điều kiện:**

```sql
-- Xóa tất cả đơn hàng bị hủy trước năm 2024
DELETE FROM don_hang
WHERE trang_thai = 'huy'
  AND ngay_dat < '2024-01-01';
```

**Xóa theo kết quả subquery:**

```sql
-- Xóa chi tiết đơn hàng của tất cả đơn bị hủy
DELETE FROM chi_tiet_don_hang
WHERE don_hang_id IN (
    SELECT id FROM don_hang
    WHERE trang_thai = 'huy'
);
```

> ⚠️ **CẢNH BÁO — Lỗi nghiêm trọng nhất với DELETE:**
>
> ```sql
> -- ❌ THẢM HỌA: Quên WHERE → XÓA TOÀN BỘ bảng!
> DELETE FROM nhan_vien;   -- Xóa sạch tất cả 12 nhân viên!
>
> -- ✅ AN TOÀN: Luôn có WHERE
> DELETE FROM nhan_vien
> WHERE id = 12;
> ```

### Thứ Tự Xóa Khi Bảng Có Khóa Ngoại

Khi xóa dữ liệu từ bảng có liên kết (Foreign Key), bạn phải xóa bảng con trước, bảng cha sau:

```
Thứ tự ĐÚNG khi xóa đơn hàng:
1. Xóa chi_tiet_don_hang trước     (bảng con — tham chiếu đến don_hang)
2. Xóa don_hang sau                (bảng cha)

Thứ tự SAI → PostgreSQL báo lỗi:
"violates foreign key constraint"
```

```sql
-- Ví dụ: Xóa hoàn toàn một đơn hàng (DH006 - đơn bị hủy)
-- Bước 1: Xóa chi tiết trước
DELETE FROM chi_tiet_don_hang
WHERE don_hang_id = (SELECT id FROM don_hang WHERE ma_don_hang = 'DH006');

-- Bước 2: Xóa đơn hàng
DELETE FROM don_hang
WHERE ma_don_hang = 'DH006';
```

## 9.3 Mẫu An Toàn: SELECT Trước Rồi Mới Sửa/Xóa

### Quy Trình 3 Bước

Đây là thói quen **bắt buộc** của mọi DBA và data analyst chuyên nghiệp:

```
Bước 1: Viết SELECT với cùng điều kiện WHERE
        → Xem trước những hàng nào sẽ bị ảnh hưởng
        → Đếm xem có bao nhiêu hàng

Bước 2: Kiểm tra kết quả — đúng chưa?
        → Có đúng số lượng không?
        → Có đúng những hàng mình muốn không?

Bước 3: Thay SELECT → UPDATE hoặc DELETE
        → Chạy câu lệnh thật sự
```

### Ví Dụ Thực Tế

**Tình huống:** Tăng lương 10% cho nhân viên phòng Kế toán đang làm việc.

```sql
-- Bước 1: XEM TRƯỚC — Những ai sẽ được tăng lương?
SELECT ho_ten, phong_ban, luong, luong * 1.10 AS luong_moi
FROM nhan_vien
WHERE phong_ban = 'Kế toán'
  AND tinh_trang = 'dang_lam';

-- Kết quả xem trước:
-- ┌──────────────────┬──────────┬──────────┬──────────┐
-- │ ho_ten           │ phong_ban│ luong    │ luong_moi│
-- ├──────────────────┼──────────┼──────────┼──────────┤
-- │ Trần Thị Mai     │ Kế toán  │ 15000000 │ 16500000 │
-- │ Hoàng Thị Dung   │ Kế toán  │ 13000000 │ 14300000 │
-- └──────────────────┴──────────┴──────────┴──────────┘
-- Có 2 hàng — đúng không?

-- Bước 2: Kiểm tra — OK, đúng 2 người phòng Kế toán đang làm
-- Bước 3: THỰC HIỆN UPDATE
UPDATE nhan_vien
SET luong = luong * 1.10
WHERE phong_ban = 'Kế toán'
  AND tinh_trang = 'dang_lam';
-- Thông báo: "UPDATE 2" → đúng 2 hàng bị ảnh hưởng ✅
```

**Mẹo:** Trong DBeaver, bạn có thể viết cả SELECT và UPDATE trong cùng một script, chạy SELECT trước (bôi đen → Ctrl+Enter), sau đó mới chạy UPDATE.

### RETURNING — Xem Kết Quả Ngay Sau UPDATE/DELETE

PostgreSQL có tính năng đặc biệt: `RETURNING` cho phép bạn **xem ngay dữ liệu vừa sửa/xóa** mà không cần chạy SELECT riêng:

```sql
-- Tăng lương 10% phòng IT → xem ngay kết quả
UPDATE nhan_vien
SET luong = luong * 1.10
WHERE phong_ban = 'IT'
RETURNING id, ho_ten, luong AS luong_moi;
```

```
  id | ho_ten          | luong_moi
  ---+-----------------+----------
   4 | Phạm Minh Châu  | 27500000
   8 | Lê Văn Hải      | 33000000
```

```sql
-- Xóa đơn hủy → xem ngay đơn nào bị xóa
DELETE FROM don_hang
WHERE trang_thai = 'huy'
RETURNING ma_don_hang, ngay_dat, tong_tien;
```

> 💡 **Tại sao RETURNING hữu ích?** Giúp bạn **xác nhận ngay** dữ liệu đã thay đổi đúng — đặc biệt quan trọng khi UPDATE/DELETE ảnh hưởng nhiều hàng. Đây là tính năng đặc biệt của PostgreSQL (MySQL/SQL Server không có).

## 9.4 TRUNCATE — Xóa Nhanh Toàn Bộ Dữ Liệu

### Khi Nào Dùng TRUNCATE?

`TRUNCATE` xóa **toàn bộ dữ liệu** trong bảng — nhanh hơn `DELETE` (không có WHERE) vì không ghi từng hàng vào log. Nhưng dùng ít hơn vì nguy hiểm hơn.

```sql
-- Xóa toàn bộ dữ liệu trong bảng (giữ lại cấu trúc bảng)
TRUNCATE TABLE ten_bang;

-- Xóa và reset lại bộ đếm SERIAL (id bắt đầu lại từ 1)
TRUNCATE TABLE ten_bang RESTART IDENTITY;

-- Xóa nhiều bảng liên kết cùng lúc (tự động xử lý thứ tự)
TRUNCATE TABLE chi_tiet_don_hang, don_hang CASCADE;
```

### So Sánh DELETE vs TRUNCATE

| | `DELETE FROM bang WHERE ...` | `DELETE FROM bang` | `TRUNCATE TABLE bang` |
|---|---|---|---|
| Xóa theo điều kiện | ✅ Có thể | ❌ Không | ❌ Không |
| Tốc độ | Chậm (từng hàng) | Chậm | Nhanh |
| Trong Transaction | ✅ ROLLBACK được | ✅ ROLLBACK được | ⚠️ Tùy cấu hình |
| Reset SERIAL | ❌ Không | ❌ Không | ✅ RESTART IDENTITY |
| Dùng khi nào | Xóa có chọn lọc | Xóa hết rồi nhập lại | Reset bảng test/staging |

## 9.5 Transaction — BEGIN/COMMIT/ROLLBACK

### Transaction Là Gì?

Transaction là **một nhóm lệnh SQL được thực hiện như một đơn vị** — hoặc tất cả thành công, hoặc không có gì thay đổi.

**Tương đương Excel:** Ctrl+Z trong Excel cho phép hoàn tác từng bước. Transaction giống như gom nhiều bước lại thành một "cụm" — có thể hoàn tác cả cụm cùng lúc.

```
Ctrl+Z trong Excel:                  Transaction trong SQL:
─────────────────────────────────    ──────────────────────────────────
Gõ → Sửa → Gõ → Sửa                 BEGIN;
Ctrl+Z → quay lại từng bước          UPDATE ... → sửa dữ liệu
                                     SELECT ... → kiểm tra
                                     ROLLBACK;  → hoàn tác toàn bộ
                                     -- hoặc
                                     COMMIT;    → xác nhận lưu
```

### Cú Pháp

```sql
BEGIN;              -- Bắt đầu transaction (ghi lại điểm có thể quay về)

-- Các lệnh SQL muốn thực hiện...
UPDATE ...;
DELETE ...;
INSERT ...;

-- Sau khi kiểm tra:
COMMIT;             -- ✅ Xác nhận — lưu tất cả thay đổi vào CSDL
-- HOẶC
ROLLBACK;           -- ↩️ Hủy bỏ — quay về trạng thái trước BEGIN
```

### Ví Dụ 1: Quy Trình Thực Hành An Toàn

```sql
-- Tình huống: Nâng lương phòng IT thêm 15%

-- Bước 1: Bắt đầu transaction
BEGIN;

-- Bước 2: Thực hiện thay đổi
UPDATE nhan_vien
SET luong = luong * 1.15
WHERE phong_ban = 'IT'
  AND tinh_trang = 'dang_lam';

-- Bước 3: Kiểm tra kết quả ngay trong transaction
SELECT ho_ten, phong_ban, luong
FROM nhan_vien
WHERE phong_ban = 'IT';
-- Kết quả hiển thị đã tăng, nhưng CHƯA LƯU vào CSDL

-- Bước 4a: Nếu đúng → lưu
COMMIT;

-- Bước 4b: Nếu sai → hủy
-- ROLLBACK;
```

> 💡 **Lưu ý quan trọng:** Bên trong một transaction đang mở (`BEGIN` rồi chưa `COMMIT`/`ROLLBACK`), **chỉ phiên làm việc của bạn** nhìn thấy dữ liệu đã thay đổi. Người khác kết nối vào cùng CSDL vẫn nhìn thấy dữ liệu cũ — cho đến khi bạn `COMMIT`.

### Ví Dụ 2: Chuyển Tiền Giữa Hai Tài Khoản (Classic Transaction Demo)

Đây là ví dụ kinh điển giải thích tại sao transaction cần thiết:

```sql
-- Tình huống: Chuyển 5 triệu từ tài khoản A → tài khoản B
-- Nếu không có transaction → có thể trừ A nhưng chưa cộng B thì bị lỗi điện

BEGIN;

UPDATE tai_khoan
SET so_du = so_du - 5000000
WHERE ma_tk = 'TK_A';          -- Trừ tài khoản A

UPDATE tai_khoan
SET so_du = so_du + 5000000
WHERE ma_tk = 'TK_B';          -- Cộng tài khoản B

-- Kiểm tra tổng tiền có đúng không
SELECT SUM(so_du) FROM tai_khoan;

COMMIT;  -- Chỉ lưu khi CẢ HAI lệnh thành công
```

Nếu lệnh thứ 2 gặp lỗi (ví dụ: TK_B không tồn tại), bạn `ROLLBACK` → lệnh đầu cũng bị hủy → tiền không biến mất.

### Ví Dụ 3: Thực Hành Với ROLLBACK

```sql
-- THỰC HÀNH: Xóa dữ liệu an toàn bằng transaction
BEGIN;

-- Xóa nhân viên id=12 (nhân viên đã nghỉ việc)
DELETE FROM nhan_vien WHERE id = 12;

-- Kiểm tra còn bao nhiêu nhân viên
SELECT COUNT(*) AS so_nv_con_lai FROM nhan_vien;
-- Kết quả: 11 (đúng — từ 12 xuống còn 11)

-- Xem lại người vừa xóa (sẽ không có kết quả vì đã xóa)
SELECT * FROM nhan_vien WHERE id = 12;

-- Quyết định: Hủy — muốn giữ lại nhân viên này
ROLLBACK;

-- Kiểm tra: nhân viên id=12 đã trở lại
SELECT * FROM nhan_vien WHERE id = 12;  -- Có kết quả ✅
```

## 9.6 SAVEPOINT — Điểm Lưu Giữa Chừng

### Khi Nào Dùng?

Trong một transaction dài với nhiều bước, đôi khi bạn chỉ muốn hoàn tác **một phần** — không muốn hủy toàn bộ. SAVEPOINT cho phép tạo "điểm lưu" giữa chừng.

```sql
BEGIN;

UPDATE nhan_vien SET luong = luong * 1.10 WHERE phong_ban = 'IT';

SAVEPOINT sau_khi_tang_it;    -- Tạo điểm lưu

UPDATE nhan_vien SET luong = luong * 1.08 WHERE phong_ban = 'Kế toán';

-- Phát hiện sai — muốn hủy chỉ phần Kế toán
ROLLBACK TO SAVEPOINT sau_khi_tang_it;
-- → Kế toán quay về, IT vẫn giữ mức đã tăng

-- Sửa lại đúng
UPDATE nhan_vien SET luong = luong * 1.05 WHERE phong_ban = 'Kế toán';

COMMIT;  -- Lưu: IT +10%, Kế toán +5%
```

> 💡 **Thực tế:** SAVEPOINT thường được dùng trong ứng dụng lập trình, ít khi dùng trực tiếp trong SQL Editor. Nhưng tốt khi biết khái niệm này tồn tại.

## 9.7 VIEW — Lưu Truy Vấn Để Dùng Lại

### View Là Gì?

View là **một truy vấn SQL được đặt tên và lưu trong database** — bạn tạo một lần, dùng nhiều lần như một bảng thông thường.

**Tương đương Excel:**
- Giống **Named Range** — bạn đặt tên cho một vùng dữ liệu để dùng trong công thức
- Giống **Pivot Table đã lưu** — pivot đã cấu hình sẵn, chỉ cần mở ra dùng
- Giống **bảng tính derived** — bảng được tính từ dữ liệu gốc, tự cập nhật khi dữ liệu gốc thay đổi

```
Không có view:                          Có view:
──────────────────────────────────      ─────────────────────────────
Mỗi lần cần báo cáo → viết lại         Tạo view 1 lần
câu SQL phức tạp 20 dòng               → SELECT * FROM ten_view
```

### Tạo View

```sql
CREATE VIEW ten_view AS
SELECT ...;
```

**Ví dụ 1: View báo cáo nhân viên đang làm việc**

```sql
CREATE VIEW v_nhan_vien_dang_lam AS
SELECT
    nv.id,
    nv.ho_ten,
    nv.phong_ban,
    nv.luong,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, nv.ngay_vao))::INTEGER  AS nam_tham_nien,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, nv.ngay_sinh))::INTEGER AS tuoi,
    CASE
        WHEN nv.luong >= 22000000 THEN 'Cao'
        WHEN nv.luong >= 17000000 THEN 'Trung bình'
        ELSE                           'Thấp'
    END AS phan_loai_luong
FROM nhan_vien nv
WHERE nv.tinh_trang = 'dang_lam';
```

Sau khi tạo, dùng view như một bảng bình thường:

```sql
-- Xem tất cả
SELECT * FROM v_nhan_vien_dang_lam;

-- Lọc theo phòng ban
SELECT * FROM v_nhan_vien_dang_lam
WHERE phong_ban = 'IT'
ORDER BY luong DESC;

-- Thống kê từ view
SELECT phong_ban, COUNT(*) AS so_nv, AVG(luong)::NUMERIC(12,0) AS luong_tb
FROM v_nhan_vien_dang_lam
GROUP BY phong_ban;
```

**Ví dụ 2: View báo cáo doanh thu**

```sql
CREATE VIEW v_bao_cao_doanh_thu AS
SELECT
    DATE_TRUNC('month', dh.ngay_dat)::DATE        AS thang,
    COUNT(dh.id)                                   AS so_don,
    SUM(dh.tong_tien)                              AS doanh_thu,
    AVG(dh.tong_tien)::NUMERIC(12,0)               AS gia_tri_tb_don
FROM don_hang dh
WHERE dh.trang_thai != 'huy'
GROUP BY DATE_TRUNC('month', dh.ngay_dat)
ORDER BY thang;
```

**Ví dụ 3: View tổng hợp khách hàng (kết hợp nhiều bảng)**

```sql
CREATE VIEW v_thong_ke_khach_hang AS
SELECT
    kh.id,
    kh.ho_ten,
    kh.thanh_pho,
    COUNT(dh.id)                                        AS tong_don,
    COALESCE(SUM(dh.tong_tien), 0)                      AS tong_tien_mua,
    MAX(dh.ngay_dat)                                    AS don_gan_nhat,
    CASE
        WHEN COALESCE(SUM(dh.tong_tien), 0) >= 10000000 THEN 'VIP'
        WHEN COALESCE(SUM(dh.tong_tien), 0) >= 1000000  THEN 'Thường'
        WHEN COUNT(dh.id) = 0                            THEN 'Chưa mua'
        ELSE                                                  'Mới'
    END AS phan_loai
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
                      AND dh.trang_thai != 'huy'
GROUP BY kh.id, kh.ho_ten, kh.thanh_pho;
```

### Quản Lý View

```sql
-- Xóa view
DROP VIEW ten_view;

-- Xóa view (không báo lỗi nếu không tồn tại)
DROP VIEW IF EXISTS ten_view;

-- Cập nhật view (xóa và tạo lại trong một lệnh)
CREATE OR REPLACE VIEW ten_view AS
SELECT ...;   -- Nội dung mới
```

### Giới Hạn Của View

```
✅ View CÓ THỂ:
   - SELECT dữ liệu từ view như từ bảng
   - Lọc, sắp xếp, JOIN view với bảng khác
   - Được tạo từ nhiều bảng và JOINs phức tạp

⚠️ View THƯỜNG KHÔNG NÊN:
   - UPDATE/DELETE qua view (phức tạp, nhiều hạn chế)
   - Thay thế index khi cần hiệu năng cao (dùng Materialized View — nâng cao hơn)
```

## 9.8 ALTER TABLE — Thay Đổi Cấu Trúc Bảng

### Khi Nào Cần ALTER TABLE?

Sau khi bảng đã được tạo và có dữ liệu, đôi khi bạn cần:
- Thêm cột mới
- Xóa cột không còn dùng
- Đổi tên cột hoặc bảng
- Thay đổi kiểu dữ liệu

**Tương đương Excel:** Chèn thêm cột, xóa cột, hoặc đổi tên tiêu đề cột.

### Các Lệnh ALTER TABLE Hay Dùng

```sql
-- Thêm cột mới
ALTER TABLE nhan_vien
ADD COLUMN so_dien_thoai VARCHAR(15);

-- Thêm cột với giá trị mặc định
ALTER TABLE nhan_vien
ADD COLUMN ngay_cap_nhat TIMESTAMP DEFAULT NOW();

-- Xóa cột
ALTER TABLE nhan_vien
DROP COLUMN so_dien_thoai;

-- Đổi tên cột
ALTER TABLE nhan_vien
RENAME COLUMN nickname TO ten_goi;

-- Đổi kiểu dữ liệu cột
ALTER TABLE nhan_vien
ALTER COLUMN so_dien_thoai TYPE VARCHAR(20);

-- Đặt NOT NULL cho cột đã có
ALTER TABLE nhan_vien
ALTER COLUMN email SET NOT NULL;

-- Bỏ ràng buộc NOT NULL
ALTER TABLE nhan_vien
ALTER COLUMN email DROP NOT NULL;

-- Đổi tên bảng
ALTER TABLE nhan_vien
RENAME TO employees;
```

### Ví Dụ Thực Tế: Thêm Cột Điểm Đánh Giá

```sql
-- Bước 1: Thêm cột mới (ban đầu toàn NULL)
ALTER TABLE nhan_vien
ADD COLUMN diem_danh_gia NUMERIC(3,1);

-- Bước 2: Nhập điểm cho từng người (hoặc cập nhật theo điều kiện)
UPDATE nhan_vien SET diem_danh_gia = 8.5 WHERE id = 1;
UPDATE nhan_vien SET diem_danh_gia = 9.0 WHERE id = 2;
-- ... (tiếp tục cho các nhân viên khác)

-- Hoặc: set mặc định cho tất cả rồi sửa từng trường hợp đặc biệt
UPDATE nhan_vien SET diem_danh_gia = 7.5 WHERE diem_danh_gia IS NULL;

-- Bước 3: Xem kết quả
SELECT ho_ten, phong_ban, luong, diem_danh_gia
FROM nhan_vien
ORDER BY diem_danh_gia DESC;
```

> ⚠️ **Cẩn thận với ALTER TABLE:**
>
> - **Xóa cột (`DROP COLUMN`):** Không phục hồi được! Luôn backup trước.
> - **Thay đổi kiểu dữ liệu:** Có thể gây lỗi nếu dữ liệu hiện có không chuyển đổi được (VD: cột có chữ không đổi sang INTEGER).
> - **Thêm NOT NULL vào cột đang có NULL:** Phải update dữ liệu NULL trước rồi mới đặt NOT NULL.

## 9.9 Import Dữ Liệu Từ CSV

### Tại Sao Cần Import CSV?

Bạn có thể đã có dữ liệu trong Excel từ nhiều năm — đây là cách đưa dữ liệu đó vào PostgreSQL để phân tích với SQL.

```
Luồng làm việc:
Excel file (.xlsx)
    │
    ▼ Save As → CSV UTF-8
CSV file (.csv)
    │
    ▼ Import
PostgreSQL table
    │
    ▼
Phân tích bằng SQL 🎉
```

### Cách 1: Dùng Giao Diện DBeaver (Dễ Nhất)

```
1. Trong DBeaver, click phải vào tên bảng muốn import
2. Chọn "Import Data"
3. Chọn "CSV" → Next
4. Click "..." chọn file CSV → Next
5. Kiểm tra mapping cột (cột CSV ↔ cột trong bảng)
6. Nhấn "Proceed" để import
```

Ưu điểm: giao diện đồ họa, dễ kiểm tra, tự xử lý encoding.

### Cách 2: Lệnh COPY (Nhanh Hơn Với File Lớn)

```sql
-- Import từ file CSV vào bảng (phải dùng đường dẫn tuyệt đối)
COPY san_pham (ten_san_pham, danh_muc, gia, so_luong_ton, ngay_nhap)
FROM 'C:/data/san_pham.csv'
WITH (
    FORMAT CSV,       -- định dạng CSV
    HEADER TRUE,      -- dòng đầu là tiêu đề (bỏ qua khi import)
    DELIMITER ',',    -- ký tự phân cách cột
    ENCODING 'UTF8'   -- encoding tiếng Việt
);
```

```sql
-- Export dữ liệu từ bảng ra CSV (ngược lại)
COPY (SELECT * FROM nhan_vien WHERE tinh_trang = 'dang_lam')
TO 'C:/data/nhan_vien_export.csv'
WITH (FORMAT CSV, HEADER TRUE, ENCODING 'UTF8');
```

### Cách 3: Dùng \copy (Trong psql Terminal)

```sql
-- Nếu dùng psql (command line), thay COPY bằng \copy
-- \copy không cần quyền superuser
\copy san_pham (ten_san_pham, danh_muc, gia)
FROM 'C:/data/san_pham.csv'
WITH (FORMAT CSV, HEADER TRUE);
```

### Chuẩn Bị File CSV Để Import Đúng

```
Checklist trước khi import:
✅ File lưu dạng CSV UTF-8 (trong Excel: File → Save As → CSV UTF-8)
✅ Dòng đầu là tên cột — khớp với tên cột trong bảng PostgreSQL
✅ Không có dữ liệu ở cột ID (SERIAL tự tăng — không cần nhập)
✅ Ngày tháng đúng format: YYYY-MM-DD (PostgreSQL đọc được)
✅ Số không có dấu phân cách hàng nghìn (1000000 thay vì 1,000,000)
✅ Chuỗi text không có dấu phẩy bên trong (nếu có → bọc trong dấu nháy kép)
```

---

### ON CONFLICT — Insert Hoặc Update Tự Động (UPSERT)

Khi import dữ liệu, bạn thường gặp tình huống: dữ liệu có thể **đã tồn tại** trong bảng. Thay vì kiểm tra thủ công rồi quyết định INSERT hay UPDATE, PostgreSQL có `ON CONFLICT`:

```sql
-- Nếu ma_sp chưa có → INSERT. Nếu đã có → UPDATE giá
INSERT INTO san_pham (ma_sp, ten_sp, gia_ban)
VALUES ('SP001', 'Cà phê đen', 35000)
ON CONFLICT (ma_sp)
DO UPDATE SET
    ten_sp  = EXCLUDED.ten_sp,
    gia_ban = EXCLUDED.gia_ban;
```

**So sánh Excel:** Giống khi bạn paste dữ liệu vào sheet đã có data — Excel hỏi "Replace?" hoặc bạn dùng `VLOOKUP` để quyết định ghi đè hay không. `ON CONFLICT` làm điều đó tự động.

> 💡 `EXCLUDED` là keyword đặc biệt — trỏ đến dữ liệu bạn **đang cố INSERT**. `EXCLUDED.gia_ban` = giá trị mới bạn muốn nhập.

```sql
-- Nếu trùng → bỏ qua (không INSERT, không báo lỗi)
INSERT INTO san_pham (ma_sp, ten_sp, gia_ban)
VALUES ('SP001', 'Cà phê đen', 35000)
ON CONFLICT (ma_sp) DO NOTHING;
```

> ⚠️ **Cột trong ON CONFLICT phải có UNIQUE constraint hoặc PRIMARY KEY** — PostgreSQL cần biết "trùng" nghĩa là gì.

## 9.10 Tổng Kết Tuần 9

### Bản Đồ Kiến Thức

```
Tuần 9 — Quản Lý Dữ Liệu
│
├── THAY ĐỔI DỮ LIỆU
│   ├── UPDATE bang SET cot = moi WHERE dk   ← Sửa dữ liệu
│   ├── DELETE FROM bang WHERE dk            ← Xóa có chọn lọc
│   └── TRUNCATE TABLE bang                  ← Xóa toàn bộ (nhanh)
│
├── AN TOÀN DỮ LIỆU
│   ├── Quy trình: SELECT trước → UPDATE/DELETE sau
│   ├── BEGIN / COMMIT / ROLLBACK           ← Transaction
│   └── SAVEPOINT / ROLLBACK TO SAVEPOINT  ← Điểm lưu giữa chừng
│
├── QUẢN LÝ CẤU TRÚC
│   └── ALTER TABLE: ADD COLUMN / DROP COLUMN / RENAME / ALTER TYPE
│
├── TÁI SỬ DỤNG TRUY VẤN
│   ├── CREATE VIEW AS SELECT ...           ← Tạo view
│   ├── SELECT * FROM view                  ← Dùng view
│   ├── CREATE OR REPLACE VIEW              ← Cập nhật view
│   └── DROP VIEW IF EXISTS                 ← Xóa view
│
└── IMPORT DỮ LIỆU
    ├── DBeaver: Import Data → CSV          ← Cách dễ nhất
    └── COPY FROM 'file.csv' WITH (...)     ← Cách SQL thuần
```

### Bảng Tóm Tắt Lệnh

```sql
-- UPDATE
UPDATE bang SET cot = moi WHERE dk;
UPDATE bang SET cot = moi WHERE cot2 = (SELECT MAX(cot2) FROM bang2);

-- DELETE
DELETE FROM bang WHERE dk;
DELETE FROM bang;           -- ⚠️ Xóa tất cả!

-- TRUNCATE
TRUNCATE TABLE bang;
TRUNCATE TABLE bang RESTART IDENTITY;

-- TRANSACTION
BEGIN;  ... COMMIT;         -- Lưu thay đổi
BEGIN;  ... ROLLBACK;       -- Hủy thay đổi

-- VIEW
CREATE VIEW v_ten AS SELECT ...;
CREATE OR REPLACE VIEW v_ten AS SELECT ...;
DROP VIEW IF EXISTS v_ten;

-- ALTER TABLE
ALTER TABLE bang ADD COLUMN cot kieu;
ALTER TABLE bang DROP COLUMN cot;
ALTER TABLE bang RENAME COLUMN cu TO moi;
```

### Quy Tắc Vàng Tuần 9

> 1. **Luôn có WHERE** trong UPDATE và DELETE — không có WHERE là "sửa/xóa tất cả"
> 2. **SELECT trước, sửa sau** — xem trước những hàng nào sẽ bị ảnh hưởng
> 3. **Dùng Transaction** khi thay đổi dữ liệu quan trọng — BEGIN trước, COMMIT sau khi kiểm tra xong
> 4. **Không DROP COLUMN** khi chưa chắc — hãy đổi tên hoặc để trống trước

### So Sánh Excel ↔ SQL — Tuần 9

| Bạn muốn làm gì? | Trong Excel | Trong SQL |
|---|---|---|
| Sửa một ô | Click → gõ lại | `UPDATE bang SET cot = moi WHERE id = x` |
| Sửa nhiều ô theo điều kiện | Find & Replace | `UPDATE bang SET cot = moi WHERE dk` |
| Xóa một hàng | Click hàng → Delete | `DELETE FROM bang WHERE id = x` |
| Xóa nhiều hàng theo điều kiện | Filter → chọn hết → Delete | `DELETE FROM bang WHERE dk` |
| Xóa toàn bộ dữ liệu, giữ cột | Chọn tất cả → Delete | `TRUNCATE TABLE bang` |
| Ctrl+Z | Ctrl+Z | `ROLLBACK` (bên trong `BEGIN`) |
| Thêm cột mới | Chèn cột | `ALTER TABLE bang ADD COLUMN cot kieu` |
| Xóa cột | Xóa cột | `ALTER TABLE bang DROP COLUMN cot` |
| Lưu Pivot Table để dùng lại | Đặt tên range / tab pivot | `CREATE VIEW v_ten AS SELECT ...` |
| Import file Excel | Copy-paste / Power Query | `COPY FROM 'file.csv'` / DBeaver import |

- [ ] Tôi biết cú pháp DELETE và luôn nhớ thêm WHERE
- [ ] Tôi quen với quy trình: chạy SELECT trước khi UPDATE/DELETE

- [ ] Tôi có thể tạo, sử dụng, và xóa VIEW
