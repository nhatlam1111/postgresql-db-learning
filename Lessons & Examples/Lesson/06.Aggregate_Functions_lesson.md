## 6.1 Hàm Tổng Hợp Là Gì? — Kết Nối Với Excel

### Câu Chuyện Mở Đầu

Sếp gửi yêu cầu cuối tháng:
- *"Công ty hiện có bao nhiêu nhân viên đang làm việc?"*
- *"Tổng quỹ lương mỗi tháng là bao nhiêu?"*
- *"Phòng nào có lương trung bình cao nhất?"*
- *"Ai có lương cao nhất, ai có lương thấp nhất?"*

**Với Excel:** Bạn gõ công thức `=COUNT(B2:B100)`, `=SUM(C2:C100)`, `=AVERAGE(C2:C100)` ngay trên bảng tính. Xong.

**Với SQL:** Bạn dùng đúng những hàm tương tự:

```
  Excel                    SQL
  ─────────────────────────────────────────────────────────
  =COUNT(B2:B100)    →    COUNT(*)  hoặc  COUNT(ten_cot)
  =SUM(C2:C100)      →    SUM(luong)
  =AVERAGE(C2:C100)  →    AVG(luong)
  =MIN(C2:C100)      →    MIN(luong)
  =MAX(C2:C100)      →    MAX(luong)
```

Sự khác biệt lớn nhất: Trong Excel, bạn viết công thức cho một **ô cụ thể** và kéo xuống. Trong SQL, hàm tổng hợp hoạt động trên **toàn bộ tập kết quả** — hoặc trên từng nhóm khi kết hợp với GROUP BY.

---

### Bức Tranh Tổng Thể — Hàm Tổng Hợp + GROUP BY

Phần quan trọng nhất tuần này là kết hợp hàm tổng hợp với GROUP BY — đây chính là **Pivot Table trong SQL**:

```
  BẢNG nhan_vien (dữ liệu thô)              KẾT QUẢ sau GROUP BY
  ┌──────────────────┬────────────┬──────────┐   ┌─────────────┬───────┬───────────────┐
  │ ho_ten           │ phong_ban  │ luong    │   │ phong_ban   │ sl_nv │ luong_tb      │
  ├──────────────────┼────────────┼──────────┤   ├─────────────┼───────┼───────────────┤
  │ Trần Thị Mai     │ Kế toán    │ 15000000 │   │ IT          │     3 │    27,666,667 │
  │ Nguyễn Văn An    │ Kinh doanh │ 20000000 │   │ Kế toán     │     3 │    15,666,667 │
  │ Lê Thị Bình      │ Nhân sự    │ 18000000 │   │ Kinh doanh  │     4 │    20,125,000 │
  │ Phạm Minh Châu   │ IT         │ 25000000 │   │ Nhân sự     │     2 │    17,000,000 │
  │ Hoàng Thị Dung   │ Kế toán    │ 13000000 │   └─────────────┴───────┴───────────────┘
  │ ...              │ ...        │ ...      │
  └──────────────────┴────────────┴──────────┘
              │                                               ↑
              │   GROUP BY phong_ban                          │
              │   + COUNT(*) AS sl_nv                         │
              │   + ROUND(AVG(luong), 0) AS luong_tb          │
              └───────────────────────────────────────────────┘
```

SQL tương ứng:
```sql
SELECT phong_ban,
       COUNT(*)                 AS sl_nv,
       ROUND(AVG(luong), 0)     AS luong_tb
FROM nhan_vien
GROUP BY phong_ban
ORDER BY luong_tb DESC;
```

### Bảng Ánh Xạ: Hàm Điều Kiện Excel → SQL

Trong Excel, bạn có các hàm "IF" để tính theo điều kiện. Trong SQL, bạn dùng **WHERE + hàm tổng hợp** hoặc **GROUP BY**:

| Công thức Excel | SQL tương đương | Giải thích |
|---|---|---|
| `=COUNT(A:A)` | `SELECT COUNT(*) FROM bang` | Đếm tất cả hàng |
| `=COUNTA(B:B)` | `SELECT COUNT(email) FROM bang` | Đếm ô không trống |
| `=COUNTIF(C:C,"IT")` | `SELECT COUNT(*) FROM bang WHERE phong_ban = 'IT'` | Đếm theo điều kiện |
| `=SUMIF(C:C,"IT",D:D)` | `SELECT SUM(luong) FROM bang WHERE phong_ban = 'IT'` | Tổng theo điều kiện |
| `=AVERAGEIF(C:C,"IT",D:D)` | `SELECT AVG(luong) FROM bang WHERE phong_ban = 'IT'` | Trung bình theo điều kiện |
| `=COUNTIFS(...)` (nhiều ĐK) | `SELECT COUNT(*) FROM bang WHERE dk1 AND dk2` | Đếm nhiều điều kiện |
| Pivot Table (nhóm + tổng) | `SELECT nhom, SUM(cot) FROM bang GROUP BY nhom` | Nhóm rồi tính |

> 💡 **Nhận ra pattern chưa?** Excel dùng hàm riêng cho mỗi loại (`COUNTIF`, `SUMIF`, `AVERAGEIF`...), còn SQL chỉ cần **1 cú pháp**: `SELECT hàm() FROM bảng WHERE điều_kiện`. Đơn giản hơn nhiều!

## 6.2 COUNT() — Đếm Số Hàng

### COUNT(*) — Đếm Tất Cả Hàng

`COUNT(*)` đếm toàn bộ hàng, **kể cả hàng có NULL** ở bất kỳ cột nào. Tương đương `=COUNTA()` trong Excel:

```sql
-- Bảng có bao nhiêu nhân viên tất cả?
SELECT COUNT(*) AS tong_nhan_vien
FROM nhan_vien;
```

```
  Kết quả:
  ┌─────────────────┐
  │ tong_nhan_vien  │
  ├─────────────────┤
  │              12 │
  └─────────────────┘
```

### COUNT(cot) — Đếm Hàng Có Giá Trị (Bỏ Qua NULL)

`COUNT(ten_cot)` chỉ đếm hàng **có giá trị** trong cột đó — bỏ qua NULL:

```
  Dữ liệu cột email:
  ┌──────────────────────┬───────────────────┬──────────────────────┐
  │ email                │ COUNT(*) đếm?     │ COUNT(email) đếm?    │
  ├──────────────────────┼───────────────────┼──────────────────────┤
  │ mai.tran@cty.com     │ ✅ có             │ ✅ có                 │
  │ NULL                 │ ✅ có             │ ❌ bỏ qua             │
  │ an.nguyen@cty.com    │ ✅ có             │ ✅ có                 │
  │ NULL                 │ ✅ có             │ ❌ bỏ qua             │
  └──────────────────────┴───────────────────┴──────────────────────┘
  COUNT(*) = 4                                COUNT(email) = 2
```

```sql
-- Đếm nhân viên ĐÃ CÓ email
SELECT COUNT(email) AS co_email
FROM nhan_vien;

-- Đếm nhân viên CHƯA CÓ email
SELECT COUNT(*) AS chua_co_email
FROM nhan_vien
WHERE email IS NULL;
```

### COUNT(DISTINCT cot) — Đếm Giá Trị Khác Nhau

Tương đương đếm số hàng còn lại sau khi dùng "Remove Duplicates" trong Excel:

```sql
-- Có bao nhiêu phòng ban khác nhau trong công ty?
SELECT COUNT(DISTINCT phong_ban) AS so_phong_ban
FROM nhan_vien;
-- Kết quả: 4 (IT, Kế toán, Kinh doanh, Nhân sự)
```

> 💡 **Phân biệt 3 dạng COUNT:**
> ```
> COUNT(*)            → Đếm tất cả hàng (kể cả hàng có NULL)
> COUNT(ten_cot)      → Đếm hàng CÓ GIÁ TRỊ (bỏ qua NULL)
> COUNT(DISTINCT cot) → Đếm giá trị KHÁC NHAU (bỏ trùng lặp)
> ```

## 6.3 SUM() và AVG() — Tổng và Trung Bình

### SUM() — Tính Tổng

```sql
-- Tổng quỹ lương toàn công ty mỗi tháng
SELECT SUM(luong) AS tong_quy_luong
FROM nhan_vien
WHERE tinh_trang = 'dang_lam';
```

```
  Kết quả:
  ┌─────────────────┐
  │ tong_quy_luong  │
  ├─────────────────┤
  │       214500000 │
  └─────────────────┘
  (214.5 triệu đồng/tháng)
```

### AVG() — Tính Trung Bình

```sql
-- Lương trung bình toàn công ty (làm tròn đến đơn vị đồng)
SELECT ROUND(AVG(luong), 0) AS luong_trung_binh
FROM nhan_vien
WHERE tinh_trang = 'dang_lam';
```

> ⚠️ **SUM() và AVG() với NULL:** Cả hai hàm đều **tự động bỏ qua NULL**. Ví dụ nếu cột lương có một hàng NULL, SUM() vẫn tính đúng tổng cho các hàng còn lại. AVG() chia tổng cho số hàng CÓ GIÁ TRỊ, không chia cho tổng số hàng.

## 6.4 MIN() và MAX() — Giá Trị Nhỏ Nhất và Lớn Nhất

```sql
-- Lương thấp nhất và cao nhất trong công ty
SELECT
    MIN(luong) AS luong_thap_nhat,
    MAX(luong) AS luong_cao_nhat
FROM nhan_vien
WHERE tinh_trang = 'dang_lam';

-- Dùng với ngày tháng: Ai vào sớm nhất, ai vào muộn nhất?
SELECT
    MIN(ngay_vao_lam) AS vao_som_nhat,
    MAX(ngay_vao_lam) AS vao_muon_nhat
FROM nhan_vien;
```

> 💡 **MIN/MAX không chỉ dùng cho số:** Có thể dùng cho ngày tháng (MIN = ngày cũ nhất, MAX = ngày mới nhất) và text (MIN = đầu bảng chữ cái, MAX = cuối bảng chữ cái).

### Tổng Hợp Tất Cả Hàm Trong Một Query

```sql
-- Bảng tổng kết nhân sự toàn công ty
SELECT
    COUNT(*)                    AS tong_nhan_vien,
    COUNT(email)                AS co_email,
    SUM(luong)                  AS tong_quy_luong,
    ROUND(AVG(luong), 0)        AS luong_trung_binh,
    MIN(luong)                  AS luong_thap_nhat,
    MAX(luong)                  AS luong_cao_nhat
FROM nhan_vien
WHERE tinh_trang = 'dang_lam';
```

```
  Kết quả (ví dụ):
  ┌───────────────┬──────────┬────────────────┬──────────────────┬─────────────────┬────────────────┐
  │ tong_nhan_vien│ co_email │ tong_quy_luong │ luong_trung_binh │ luong_thap_nhat │ luong_cao_nhat │
  ├───────────────┼──────────┼────────────────┼──────────────────┼─────────────────┼────────────────┤
  │            11 │        9 │      214500000 │         19500000 │        13000000 │       30000000 │
  └───────────────┴──────────┴────────────────┴──────────────────┴─────────────────┴────────────────┘
```

## 6.5 GROUP BY — Nhóm Dữ Liệu (= Pivot Table)

### Pivot Table Trong Excel vs GROUP BY Trong SQL

Đây là mối liên hệ quan trọng nhất tuần này:

```
  EXCEL — Pivot Table                         SQL — GROUP BY
  ──────────────────────────────────────────────────────────────────────
  Kéo "Phòng ban" vào vùng Rows          →   GROUP BY phong_ban
  Kéo "Nhân viên" vào Values → Count     →   COUNT(*) trong SELECT
  Kéo "Lương" vào Values → Sum           →   SUM(luong) trong SELECT
  Kéo "Lương" vào Values → Average       →   AVG(luong) trong SELECT
```

```
  Pivot Table Excel trông như vầy:

  Row Labels   │ Count of Nhân viên │ Sum of Lương │ Average of Lương
  ─────────────┼────────────────────┼──────────────┼──────────────────
  IT           │          3         │   83,000,000 │      27,666,667
  Kế toán      │          3         │   47,000,000 │      15,666,667
  Kinh doanh   │          4         │   80,500,000 │      20,125,000
  Nhân sự      │          2         │   34,000,000 │      17,000,000
  Grand Total  │         12         │  244,500,000 │      20,375,000

  SQL tương đương:
  SELECT
      phong_ban,
      COUNT(*)                    AS so_nhan_vien,
      SUM(luong)                  AS tong_luong,
      ROUND(AVG(luong), 0)        AS luong_trung_binh
  FROM nhan_vien
  GROUP BY phong_ban
  ORDER BY phong_ban;
```

---

### Cú Pháp GROUP BY

```
  ┌────────────────────────────────────────────────────────────────────┐
  │                        CÚ PHÁP GROUP BY                            │
  ├────────────────────────────────────────────────────────────────────┤
  │                                                                    │
  │  SELECT   cot_nhom, ham_tong_hop(cot_tinh)                         │
  │  FROM     ten_bang                                                 │
  │  WHERE    dieu_kien_loc_hang        ← Lọc hàng TRƯỚC khi nhóm     │
  │  GROUP BY cot_nhom;                 ← Nhóm theo cột này            │
  │                                                                    │
  │  QUY TẮC VÀNG:                                                     │
  │  Mọi cột trong SELECT phải thuộc một trong hai loại:               │
  │  ├── Cột nhóm:     có trong GROUP BY                               │
  │  └── Cột tổng hợp: bên trong COUNT(), SUM(), AVG(), MIN(), MAX()   │
  │                                                                    │
  └────────────────────────────────────────────────────────────────────┘
```

### Quy Tắc Vàng — Lỗi Hay Gặp Nhất

```
  Giải thích tại sao quy tắc này tồn tại:

  Khi GROUP BY phong_ban, bảng được gom thành 4 nhóm.
  Mỗi nhóm có NHIỀU hàng, VD nhóm IT có 3 hàng:
  ┌──────────────────┬────────────┬──────────┐
  │ Phạm Minh Châu   │ IT         │ 25000000 │  ← hàng 1
  │ Đỗ Thị Phương    │ IT         │ 30000000 │  ← hàng 2
  │ Ngô Minh Khánh   │ IT         │ 28000000 │  ← hàng 3
  └──────────────────┴────────────┴──────────┘

  Nếu bạn SELECT ho_ten, máy không biết hiển thị ho_ten của hàng nào!
  → Đó là lý do bạn phải dùng hàm tổng hợp cho các cột không phải cột nhóm.
```

```sql
-- ❌ LỖI: ho_ten có 3 giá trị trong nhóm IT — máy không biết chọn cái nào
SELECT phong_ban, ho_ten, COUNT(*)
FROM nhan_vien
GROUP BY phong_ban;
-- ERROR: column "nhan_vien.ho_ten" must appear in the GROUP BY clause
--        or be used in an aggregate function

-- ✅ ĐÚNG: Chỉ lấy cột nhóm và hàm tổng hợp
SELECT phong_ban, COUNT(*) AS so_nhan_vien
FROM nhan_vien
GROUP BY phong_ban;

-- ✅ ĐÚNG: Nếu muốn cả ho_ten thì phải thêm vào GROUP BY
-- (nhưng kết quả lúc này mỗi người một nhóm — ít có ý nghĩa)
SELECT phong_ban, ho_ten, COUNT(*)
FROM nhan_vien
GROUP BY phong_ban, ho_ten;
```

> 💡 **Dễ nhớ hơn qua Pivot Table:** Trong Pivot Table, cột nhóm là **vùng Rows** (bạn kéo vào đây), hàm tổng hợp là **vùng Values** (phải là số tổng hợp, không phải ô dữ liệu đơn lẻ). GROUP BY = Rows, hàm tổng hợp = Values.

### Ví Dụ GROUP BY Thực Tế

```sql
-- Đếm số nhân viên theo từng phòng ban
SELECT phong_ban, COUNT(*) AS so_nhan_vien
FROM nhan_vien
GROUP BY phong_ban
ORDER BY so_nhan_vien DESC;

-- Tổng lương và lương trung bình theo phòng ban (chỉ nhân viên đang làm)
SELECT
    phong_ban,
    COUNT(*)                    AS so_nhan_vien,
    SUM(luong)                  AS tong_luong,
    ROUND(AVG(luong), 0)        AS luong_trung_binh,
    MIN(luong)                  AS luong_thap_nhat,
    MAX(luong)                  AS luong_cao_nhat
FROM nhan_vien
WHERE tinh_trang = 'dang_lam'
GROUP BY phong_ban
ORDER BY luong_trung_binh DESC;
```

## 6.6 GROUP BY Nhiều Cột

Giống như thêm nhiều field vào vùng Rows trong Pivot Table — bạn nhóm theo nhiều tiêu chí cùng lúc:

```
  Pivot Table Excel với 2 fields trong Rows:

  Phòng ban    │ Tình trạng  │ Count
  ─────────────┼─────────────┼───────
  IT           │ dang_lam    │   3
  Kế toán      │ dang_lam    │   3
  Kinh doanh   │ dang_lam    │   3
               │ nghi_viec   │   1
  Nhân sự      │ dang_lam    │   2
```

```sql
-- Đếm nhân viên theo từng phòng ban VÀ từng tình trạng
SELECT
    phong_ban,
    tinh_trang,
    COUNT(*) AS so_nhan_vien
FROM nhan_vien
GROUP BY phong_ban, tinh_trang
ORDER BY phong_ban, tinh_trang;
```

```
  Kết quả:
  ┌─────────────┬────────────┬──────────────┐
  │ phong_ban   │ tinh_trang │ so_nhan_vien │
  ├─────────────┼────────────┼──────────────┤
  │ IT          │ dang_lam   │            3 │
  │ Kế toán     │ dang_lam   │            3 │
  │ Kinh doanh  │ dang_lam   │            3 │
  │ Kinh doanh  │ nghi_viec  │            1 │
  │ Nhân sự     │ dang_lam   │            2 │
  └─────────────┴────────────┴──────────────┘
```

> 💡 Quy tắc vàng vẫn áp dụng: tất cả cột nhóm (`phong_ban`, `tinh_trang`) đều phải có trong GROUP BY.

## 6.7 HAVING — Lọc Sau Khi Nhóm

### HAVING Là Gì?

Sau khi GROUP BY tạo ra các nhóm, đôi khi bạn chỉ muốn giữ lại những nhóm thỏa điều kiện nào đó. **HAVING** là bộ lọc áp dụng **sau khi đã nhóm xong**.

```
  Ví dụ: "Chỉ hiển thị phòng ban có từ 3 nhân viên trở lên"

  Bước 1 — GROUP BY tạo nhóm:           Bước 2 — HAVING lọc nhóm:
  ┌─────────────┬──────────────┐         ┌─────────────┬──────────────┐
  │ phong_ban   │ so_nhan_vien │         │ phong_ban   │ so_nhan_vien │
  ├─────────────┼──────────────┤         ├─────────────┼──────────────┤
  │ IT          │      3       │  ✅ ≥3  │ IT          │      3       │
  │ Kế toán     │      3       │  ✅ ≥3  │ Kế toán     │      3       │
  │ Kinh doanh  │      4       │  ✅ ≥3  │ Kinh doanh  │      4       │
  │ Nhân sự     │      2       │  ❌ <3  └─────────────┴──────────────┘
  └─────────────┴──────────────┘          (Nhân sự bị loại)
```

```sql
-- Chỉ lấy phòng ban có từ 3 nhân viên trở lên
SELECT phong_ban, COUNT(*) AS so_nhan_vien
FROM nhan_vien
GROUP BY phong_ban
HAVING COUNT(*) >= 3
ORDER BY so_nhan_vien DESC;
```

### Thêm Ví Dụ HAVING

```sql
-- Phòng ban có lương trung bình trên 18 triệu
SELECT
    phong_ban,
    ROUND(AVG(luong), 0) AS luong_trung_binh
FROM nhan_vien
WHERE tinh_trang = 'dang_lam'
GROUP BY phong_ban
HAVING AVG(luong) > 18000000
ORDER BY luong_trung_binh DESC;

-- Phòng ban có tổng quỹ lương trên 60 triệu/tháng
SELECT
    phong_ban,
    SUM(luong) AS tong_luong
FROM nhan_vien
WHERE tinh_trang = 'dang_lam'
GROUP BY phong_ban
HAVING SUM(luong) > 60000000
ORDER BY tong_luong DESC;
```

> 💡 **HAVING trong Excel:** Gần nhất là khi bạn Filter trực tiếp trên bảng kết quả của Pivot Table. Nhưng trong Excel bạn làm tay sau khi thấy kết quả; trong SQL, HAVING làm điều đó tự động ngay trong cùng câu lệnh.

## 6.8 Phân Biệt WHERE vs HAVING — Dễ Nhầm Nhất!

Đây là điểm dễ nhầm nhất tuần này. Cần nhớ rõ:

```
  ┌─────────────────────────────────┬──────────────────────────────────────┐
  │             WHERE               │               HAVING                  │
  ├─────────────────────────────────┼──────────────────────────────────────┤
  │ Lọc HÀNG                        │ Lọc NHÓM                              │
  │ Chạy TRƯỚC GROUP BY             │ Chạy SAU GROUP BY                     │
  │ Không dùng hàm tổng hợp         │ Thường dùng hàm tổng hợp              │
  │ Điều kiện trên từng hàng đơn lẻ │ Điều kiện trên kết quả đã tổng hợp   │
  └─────────────────────────────────┴──────────────────────────────────────┘
```

### Hình Dung Qua Sơ Đồ Luồng

```
  Toàn bộ bảng nhan_vien (12 hàng)
          │
          ▼
  WHERE tinh_trang = 'dang_lam'        ← Lọc HÀNG: 11 hàng còn lại
          │
          ▼
  GROUP BY phong_ban                    ← Tạo nhóm: 4 nhóm
          │
          ▼
  Tính COUNT(*), AVG(luong)...          ← Hàm tổng hợp chạy trên mỗi nhóm
          │
          ▼
  HAVING AVG(luong) > 18000000         ← Lọc NHÓM: 2 nhóm còn lại
          │
          ▼
  SELECT + ORDER BY                     ← Trình bày kết quả cuối
```

### Ví Dụ So Sánh Trực Tiếp

```
  Câu hỏi 1: "Tính lương TB theo phòng — chỉ tính nhân viên đang làm việc"
  → Lọc TRƯỚC khi nhóm → WHERE

  Câu hỏi 2: "Chỉ hiển thị phòng có lương TB trên 18 triệu"
  → Lọc SAU khi đã tính TB → HAVING
```

```sql
-- Kết hợp cả hai trong một query:
SELECT
    phong_ban,
    ROUND(AVG(luong), 0) AS luong_trung_binh
FROM nhan_vien
WHERE tinh_trang = 'dang_lam'       -- ← WHERE: lọc hàng trước khi nhóm
GROUP BY phong_ban
HAVING AVG(luong) > 18000000        -- ← HAVING: lọc nhóm sau khi tính TB
ORDER BY luong_trung_binh DESC;
```

### Lỗi Phổ Biến — Dùng WHERE Thay HAVING

```sql
-- ❌ LỖI: Không thể dùng hàm tổng hợp trong WHERE
SELECT phong_ban, COUNT(*) AS so_nhan_vien
FROM nhan_vien
WHERE COUNT(*) >= 3           -- ERROR: aggregate functions are not allowed in WHERE
GROUP BY phong_ban;

-- ✅ ĐÚNG: Hàm tổng hợp phải ở trong HAVING
SELECT phong_ban, COUNT(*) AS so_nhan_vien
FROM nhan_vien
GROUP BY phong_ban
HAVING COUNT(*) >= 3;
```

### Bảng Quyết Định Nhanh

```
  Điều kiện bạn muốn lọc            → Dùng gì?
  ──────────────────────────────────────────────────────────────────
  phong_ban = 'IT'                  → WHERE   (cột bình thường)
  luong > 20000000                  → WHERE   (cột bình thường)
  tinh_trang = 'dang_lam'           → WHERE   (cột bình thường)
  ngay_vao_lam >= '2020-01-01'      → WHERE   (cột bình thường)
  ──────────────────────────────────────────────────────────────────
  COUNT(*) >= 3                     → HAVING  (hàm tổng hợp)
  AVG(luong) > 18000000             → HAVING  (hàm tổng hợp)
  SUM(luong) > 60000000             → HAVING  (hàm tổng hợp)
  MAX(luong) < 30000000             → HAVING  (hàm tổng hợp)
```

> 💡 **Nguyên tắc nhớ nhanh:** Thấy hàm tổng hợp trong điều kiện (COUNT, SUM, AVG, MIN, MAX) → HAVING. Điều kiện thông thường trên từng hàng → WHERE.

## 6.9 Kết Hợp WHERE + GROUP BY + HAVING + ORDER BY

### Ví Dụ Thực Tế Công Việc

```sql
-- Yêu cầu từ sếp:
-- "Với nhân viên đang làm việc, cho tôi xem các phòng ban có từ 2 người trở lên
--  và lương trung bình trên 17 triệu. Sắp xếp theo lương trung bình cao nhất."

SELECT
    phong_ban,
    COUNT(*)                    AS so_nhan_vien,
    ROUND(AVG(luong), 0)        AS luong_trung_binh,
    MIN(luong)                  AS luong_thap_nhat,
    MAX(luong)                  AS luong_cao_nhat
FROM nhan_vien
WHERE tinh_trang = 'dang_lam'          -- Bước 1: Lọc chỉ nhân viên đang làm
GROUP BY phong_ban                      -- Bước 2: Nhóm theo phòng
HAVING COUNT(*) >= 2                    -- Bước 3: Chỉ phòng có ít nhất 2 người
   AND AVG(luong) > 17000000            -- Bước 4: Và lương trung bình > 17 triệu
ORDER BY luong_trung_binh DESC;         -- Bước 5: Sắp xếp kết quả
```

```
  Kết quả mong đợi:
  ┌─────────────┬──────────────┬──────────────────┬─────────────────┬────────────────┐
  │ phong_ban   │ so_nhan_vien │ luong_trung_binh │ luong_thap_nhat │ luong_cao_nhat │
  ├─────────────┼──────────────┼──────────────────┼─────────────────┼────────────────┤
  │ IT          │            3 │         27666667 │        25000000 │       30000000 │
  │ Kinh doanh  │            3 │         20333333 │        20000000 │       21000000 │
  │ Nhân sự     │            2 │         17000000 │        16000000 │       18000000 │
  └─────────────┴──────────────┴──────────────────┴─────────────────┴────────────────┘
  (Kế toán bị loại vì lương trung bình dưới 17 triệu)
```

### Thêm Ví Dụ Tổng Hợp

```sql
-- Phân tích thâm niên theo phòng ban:
-- Mỗi phòng có mấy người, ngày vào sớm nhất, ngày vào muộn nhất
SELECT
    phong_ban,
    COUNT(*)                    AS so_nhan_vien,
    MIN(ngay_vao_lam)           AS vao_som_nhat,
    MAX(ngay_vao_lam)           AS vao_muon_nhat
FROM nhan_vien
WHERE tinh_trang = 'dang_lam'
GROUP BY phong_ban
ORDER BY phong_ban;

-- Thống kê email theo phòng ban:
-- Mỗi phòng có mấy người, mấy người có email
SELECT
    phong_ban,
    COUNT(*)        AS tong_nhan_vien,
    COUNT(email)    AS co_email,
    COUNT(*) - COUNT(email)  AS chua_co_email
FROM nhan_vien
GROUP BY phong_ban
ORDER BY chua_co_email DESC;
```

## 6.10 Thứ Tự Thực Thi Đầy Đủ

Tuần này bổ sung GROUP BY và HAVING vào thứ tự thực thi. Đây là bức tranh hoàn chỉnh:

```
  Thứ tự VIẾT (bạn gõ)             Thứ tự THỰC THI (máy chạy)
  ─────────────────────────────     ──────────────────────────────────────
  SELECT   ...                      1. FROM      nhan_vien      ← Lấy bảng
  FROM     nhan_vien                2. WHERE     tinh_trang=... ← Lọc hàng
  WHERE    tinh_trang = '...'       3. GROUP BY  phong_ban      ← Tạo nhóm
  GROUP BY phong_ban                4. HAVING    COUNT(*)>=2    ← Lọc nhóm
  HAVING   COUNT(*) >= 2            5. SELECT    ...            ← Chọn cột
  ORDER BY luong_tb DESC            6. ORDER BY  luong_tb DESC  ← Sắp xếp
  LIMIT    5                        7. LIMIT     5              ← Giới hạn
```

### Hệ Quả Quan Trọng — Alias Trong HAVING và GROUP BY

```sql
-- ❌ LỖI: HAVING không dùng được alias (HAVING chạy TRƯỚC SELECT)
SELECT phong_ban, ROUND(AVG(luong), 0) AS luong_tb
FROM nhan_vien
GROUP BY phong_ban
HAVING luong_tb > 18000000;    -- ERROR: column "luong_tb" does not exist

-- ✅ ĐÚNG: Lặp lại hàm tổng hợp trong HAVING
SELECT phong_ban, ROUND(AVG(luong), 0) AS luong_tb
FROM nhan_vien
GROUP BY phong_ban
HAVING AVG(luong) > 18000000;  -- ✅ Lặp lại AVG(luong), không dùng alias
```

```
  Tổng kết quy tắc alias trong tất cả các mệnh đề:
  ┌────────────────────────────────────────────────────────────────────┐
  │  WHERE    → ❌ KHÔNG dùng alias  (chạy TRƯỚC SELECT — bước 2)     │
  │  GROUP BY → ❌ KHÔNG dùng alias  (chạy TRƯỚC SELECT — bước 3)     │
  │  HAVING   → ❌ KHÔNG dùng alias  (chạy TRƯỚC SELECT — bước 4)     │
  │  ORDER BY → ✅ DÙNG ĐƯỢC alias   (chạy SAU SELECT  — bước 6)      │
  └────────────────────────────────────────────────────────────────────┘
```

> 💡 **Ngoại lệ của PostgreSQL:** PostgreSQL cho phép dùng alias trong GROUP BY và HAVING do cơ chế tối ưu hóa nội bộ. Nhưng đây là đặc thù của PostgreSQL — SQL chuẩn và các database khác (MySQL, SQL Server) không cho phép. Để viết code dễ di chuyển, tốt nhất không dùng alias trong GROUP BY/HAVING.

## Tổng Kết Tuần 6

### Bảng Tra Cứu Nhanh

| Nhu cầu | SQL |
|---|---|
| Đếm tất cả hàng | `COUNT(*)` |
| Đếm hàng có giá trị (bỏ NULL) | `COUNT(ten_cot)` |
| Đếm giá trị khác nhau | `COUNT(DISTINCT ten_cot)` |
| Tính tổng | `SUM(ten_cot)` |
| Tính trung bình | `AVG(ten_cot)` |
| Giá trị nhỏ nhất | `MIN(ten_cot)` |
| Giá trị lớn nhất | `MAX(ten_cot)` |
| Nhóm dữ liệu | `GROUP BY ten_cot` |
| Nhóm theo nhiều cột | `GROUP BY cot1, cot2` |
| Lọc nhóm sau khi tổng hợp | `HAVING ham_tong_hop(...) dieu_kien` |

### Checklist Tự Kiểm Tra

Trước khi qua Tuần 7, hãy chắc chắn bạn có thể:

- [ ] Dùng COUNT(*), COUNT(cot), COUNT(DISTINCT cot) và giải thích sự khác nhau
- [ ] Dùng SUM(), AVG(), MIN(), MAX() trên một cột số
- [ ] Dùng MIN(), MAX() trên cột ngày tháng
- [ ] Viết GROUP BY để nhóm dữ liệu theo một cột
- [ ] Viết GROUP BY nhiều cột
- [ ] Giải thích quy tắc vàng: cột trong SELECT phải có trong GROUP BY hoặc bên trong hàm tổng hợp
- [ ] Dùng HAVING để lọc nhóm sau khi tổng hợp
- [ ] Phân biệt khi nào dùng WHERE, khi nào dùng HAVING
- [ ] Kết hợp đầy đủ: WHERE + GROUP BY + HAVING + ORDER BY
- [ ] Hiểu tại sao không dùng alias trong HAVING nhưng được trong ORDER BY

### So Sánh Excel ↔ SQL — Tuần 6

| Excel | SQL |
|---|---|
| `=COUNT(B2:B100)` | `SELECT COUNT(*) FROM bang` |
| `=COUNTA(B2:B100)` | `SELECT COUNT(ten_cot) FROM bang` |
| `=SUM(C2:C100)` | `SELECT SUM(luong) FROM bang` |
| `=AVERAGE(C2:C100)` | `SELECT AVG(luong) FROM bang` |
| `=MIN(C2:C100)` | `SELECT MIN(luong) FROM bang` |
| `=MAX(C2:C100)` | `SELECT MAX(luong) FROM bang` |
| Pivot Table — kéo field vào Rows | `GROUP BY ten_cot` |
| Pivot Table — kéo field vào Values (Sum) | `SUM(ten_cot)` trong SELECT |
| Pivot Table — kéo field vào Values (Count) | `COUNT(*)` trong SELECT |
| Filter dữ liệu nguồn trước khi tạo Pivot | `WHERE dieu_kien` (trước GROUP BY) |
| Filter trên kết quả Pivot Table | `HAVING dieu_kien` (sau GROUP BY) |
