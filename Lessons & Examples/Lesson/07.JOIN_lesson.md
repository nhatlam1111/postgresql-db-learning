## 7.1 Vấn Đề Dữ Liệu Lặp Trong Excel

### Câu Chuyện Mở Đầu

Bạn đang quản lý đơn hàng trong Excel. Mỗi đơn ghi đầy đủ thông tin khách hàng:

```
  Bảng đơn hàng Excel:
  ┌──────┬──────────────────┬────────────┬──────────────────┬───────────────┬──────────┐
  │ DH#  │ Tên KH           │ SĐT KH     │ Địa chỉ KH       │ Ngày đặt      │ Tiền     │
  ├──────┼──────────────────┼────────────┼──────────────────┼───────────────┼──────────┤
  │ DH01 │ Trần Thị Mai     │ 0901123456 │ 10 Nguyễn Huệ   │ 2024-01-05    │ 500,000  │
  │ DH02 │ Nguyễn Văn An    │ 0912234567 │ 25 Lê Lợi       │ 2024-01-12    │ 300,000  │
  │ DH03 │ Trần Thị Mai     │ 0901123456 │ 10 Nguyễn Huệ   │ 2024-01-20    │ 800,000  │  ← lặp!
  │ DH04 │ Trần Thị Mai     │ 0901123456 │ 10 Nguyễn Huệ   │ 2024-02-03    │ 150,000  │  ← lặp!
  │ DH05 │ Nguyễn Văn An    │ 0912234567 │ 25 Lê Lợi       │ 2024-02-10    │ 620,000  │  ← lặp!
  └──────┴──────────────────┴────────────┴──────────────────┴───────────────┴──────────┘
```

Chị Trần Thị Mai mua 3 lần → Thông tin của chị bị lặp 3 lần. Nếu chị chuyển nhà, bạn phải sửa **3 hàng** — và có thể bỏ sót!

**Đây là "bẫy" phổ biến nhất của Excel khi dữ liệu có quan hệ.**

Những vấn đề phát sinh:
- Dễ nhập sai (SĐT ghi khác nhau ở hai hàng)
- Cập nhật sót (thay địa chỉ nhưng chỉ sửa 2/3 hàng)
- File nặng vì dữ liệu dư thừa
- Khó phân tích (đếm số khách riêng biệt phải xử lý phức tạp)

## 7.2 Giải Pháp: Tách Bảng & Liên Kết

### Cách Database Giải Quyết

Thay vì nhét tất cả vào một bảng, CSDL tách ra **2 bảng** và dùng **mã số** để liên kết:

```
  Bảng khach_hang:                       Bảng don_hang:
  ┌────┬──────────────────┬────────────┐  ┌──────┬────────────┬───────────────┬──────────┐
  │ id │ ho_ten           │ so_dien_thoai │  │ id   │ khach_hang_id │ ngay_dat   │ tong_tien│
  ├────┼──────────────────┼────────────┤  ├──────┼────────────┼───────────────┼──────────┤
  │  1 │ Trần Thị Mai     │ 0901123456 │  │ DH01 │    1       │ 2024-01-05    │  500000  │
  │  2 │ Nguyễn Văn An    │ 0912234567 │  │ DH02 │    2       │ 2024-01-12    │  300000  │
  └────┴──────────────────┴────────────┘  │ DH03 │    1       │ 2024-01-20    │  800000  │
                                          │ DH04 │    1       │ 2024-02-03    │  150000  │
       ↑ Mỗi khách chỉ lưu 1 lần         │ DH05 │    2       │ 2024-02-10    │  620000  │
                                          └──────┴────────────┴───────────────┴──────────┘
                                                      ↑ khach_hang_id = 1 → tham chiếu đến
                                                         Trần Thị Mai trong bảng kia
```

Bây giờ nếu chị Mai chuyển nhà → chỉ sửa **1 hàng** trong bảng `khach_hang` — tất cả đơn hàng tự động cập nhật!

### Primary Key & Foreign Key

Đây là hai khái niệm cốt lõi:

```
  ┌─────────────────────────────────────────────────────────────────────┐
  │  PRIMARY KEY (Khóa chính)                                           │
  │  → Cột định danh duy nhất cho mỗi hàng trong bảng đó               │
  │  → Không được NULL, không được trùng                                │
  │  → Ví dụ: id trong bảng khach_hang (mỗi khách có 1 id riêng)       │
  ├─────────────────────────────────────────────────────────────────────┤
  │  FOREIGN KEY (Khóa ngoại)                                           │
  │  → Cột tham chiếu đến Primary Key của bảng khác                    │
  │  → Là "cầu nối" giữa hai bảng                                       │
  │  → Ví dụ: khach_hang_id trong bảng don_hang (trỏ đến id của khach_hang) │
  └─────────────────────────────────────────────────────────────────────┘
```

```
  Bảng khach_hang                           Bảng don_hang
  ┌────────────────────────┐                ┌────────────────────────┐
  │ id  ← PRIMARY KEY      │                │ id  ← PRIMARY KEY      │
  │ ho_ten                 │                │ khach_hang_id ← FOREIGN KEY ─┐
  │ so_dien_thoai          │                │ ngay_dat               │     │
  │ email                  │ ←──────────────│ tong_tien              │     │
  └────────────────────────┘    "khach_hang_id └────────────────────────┘  │
                                 trỏ đến                                   │
                                 id của                                    │
                                 khach_hang"                               │
                                                                           │
  ← Mối quan hệ: 1 khách có NHIỀU đơn hàng ─────────────────────────────┘
```

> 💡 **Tương đương Excel:** Primary Key giống cột **Mã KH** duy nhất trong sheet Khách hàng. Foreign Key giống cột **Mã KH** trong sheet Đơn hàng — để biết đơn đó của khách nào (như VLOOKUP cần cột tra cứu).

## 7.3 INNER JOIN — Lấy Dữ Liệu Có Ở Cả Hai Bảng

### INNER JOIN Là Gì?

INNER JOIN kết nối hai bảng và chỉ lấy những hàng **có khớp ở CẢ HAI bảng**. Đây chính là cách VLOOKUP hoạt động trong Excel — nếu không tìm thấy khớp, hàng đó không xuất hiện trong kết quả.

```
  Excel — VLOOKUP:                      SQL — INNER JOIN:
  ─────────────────────────────────────────────────────────────────────
  Bảng đơn hàng (main data)             FROM don_hang dh
  Tra theo cột Mã KH                    INNER JOIN khach_hang kh
  Trong sheet Khách hàng                ON dh.khach_hang_id = kh.id
  Lấy về cột Tên KH                     SELECT kh.ho_ten, dh.tong_tien
```

### Cú Pháp INNER JOIN

```
  ┌─────────────────────────────────────────────────────────────────────┐
  │                      CÚ PHÁP INNER JOIN                             │
  ├─────────────────────────────────────────────────────────────────────┤
  │                                                                     │
  │  SELECT  bang1.cot1, bang2.cot2, ...                                │
  │  FROM    bang1                         ← Bảng chính                 │
  │  INNER JOIN bang2                      ← Bảng muốn kết nối         │
  │  ON bang1.khoa_ngoai = bang2.khoa_chinh;  ← Điều kiện nối          │
  │                                                                     │
  │  Hoặc viết ngắn (INNER có thể bỏ):                                  │
  │  JOIN bang2 ON bang1.col = bang2.col                                │
  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘
```

### Ví Dụ — Xem Đơn Hàng Kèm Tên Khách

```sql
-- Hiển thị đơn hàng kèm thông tin khách hàng
SELECT
    dh.ma_don_hang,
    kh.ho_ten           AS ten_khach,
    kh.so_dien_thoai,
    dh.ngay_dat,
    dh.tong_tien
FROM don_hang dh
INNER JOIN khach_hang kh ON dh.khach_hang_id = kh.id
ORDER BY dh.ngay_dat DESC;
```

```
  Kết quả:
  ┌─────────────┬──────────────────┬────────────┬────────────┬───────────┐
  │ ma_don_hang │ ten_khach        │ so_dien_thoai │ ngay_dat │ tong_tien │
  ├─────────────┼──────────────────┼────────────┼────────────┼───────────┤
  │ DH012       │ Nguyễn Văn An    │ 0912234567 │ 2024-04-18 │  11000000 │
  │ DH011       │ Trần Thị Mai     │ 0901123456 │ 2024-04-10 │  28000000 │
  │ ...         │ ...              │ ...        │ ...        │ ...       │
  └─────────────┴──────────────────┴────────────┴────────────┴───────────┘
```

### Table Alias — Viết Gọn Tên Bảng

Khi tên bảng dài, bạn đặt alias (tên tắt) để viết nhanh hơn:

```
  Không có alias (dài):              Có alias (ngắn gọn):
  ┌──────────────────────────┐       ┌──────────────────────────┐
  │ FROM don_hang             │       │ FROM don_hang dh          │
  │ JOIN khach_hang           │       │ JOIN khach_hang kh        │
  │ ON don_hang.khach_hang_id │       │ ON dh.khach_hang_id       │
  │   = khach_hang.id         │       │   = kh.id                 │
  │ SELECT don_hang.ma_don,   │       │ SELECT dh.ma_don,         │
  │   khach_hang.ho_ten       │       │   kh.ho_ten               │
  └──────────────────────────┘       └──────────────────────────┘
```

> 💡 **Quy ước đặt alias bảng:** Thường dùng 2-3 chữ cái đầu của tên bảng: `don_hang` → `dh`, `khach_hang` → `kh`, `nhan_vien` → `nv`, `san_pham` → `sp`.

### Tại Sao Phải Viết `bang.cot` Thay Vì Chỉ `cot`?

Khi JOIN nhiều bảng, nhiều bảng có thể có cột **cùng tên** (ví dụ cả hai bảng đều có cột `id`). Phải chỉ rõ bảng nào:

```sql
-- ❌ LỖI: Cột "id" tồn tại ở cả hai bảng — máy không biết lấy từ đâu
SELECT id, ho_ten, tong_tien
FROM don_hang
JOIN khach_hang ON don_hang.khach_hang_id = khach_hang.id;
-- ERROR: column reference "id" is ambiguous

-- ✅ ĐÚNG: Chỉ rõ bảng nào
SELECT dh.id AS ma_don, kh.ho_ten, dh.tong_tien
FROM don_hang dh
JOIN khach_hang kh ON dh.khach_hang_id = kh.id;
```

## 7.4 LEFT JOIN — Lấy Tất Cả Từ Bảng Trái

### LEFT JOIN Là Gì?

LEFT JOIN lấy **TẤT CẢ hàng từ bảng bên trái** (bảng đầu tiên viết trong FROM), dù có hay không có khớp ở bảng bên phải. Hàng không có khớp sẽ điền `NULL` cho các cột của bảng phải.

```
  INNER JOIN:                           LEFT JOIN:
  ┌──────────────────────────────┐      ┌────────────────────────────────┐
  │ Chỉ lấy hàng KHỚP ở cả hai  │      │ Lấy TẤT CẢ từ bảng trái       │
  │                              │      │ + hàng khớp từ bảng phải       │
  │  Khách A có đơn → ✅ lấy     │      │  Khách A có đơn → ✅ lấy       │
  │  Khách B có đơn → ✅ lấy     │      │  Khách B có đơn → ✅ lấy       │
  │  Khách C KHÔNG đơn → ❌ bỏ  │      │  Khách C KHÔNG đơn → ✅ lấy!   │
  │                              │      │    (đơn hàng sẽ là NULL)        │
  └──────────────────────────────┘      └────────────────────────────────┘
```

### Ví Dụ — Khách Hàng Chưa Có Đơn

```sql
-- Lấy TẤT CẢ khách hàng, kể cả người chưa có đơn hàng nào
SELECT
    kh.ho_ten,
    kh.so_dien_thoai,
    dh.ma_don_hang,
    dh.ngay_dat,
    dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
ORDER BY kh.ho_ten;
```

```
  Kết quả:
  ┌──────────────────┬────────────┬─────────────┬────────────┬───────────┐
  │ ho_ten           │ so_dien_thoai │ ma_don_hang │ ngay_dat │ tong_tien │
  ├──────────────────┼────────────┼─────────────┼────────────┼───────────┤
  │ Trần Thị Mai     │ 0901123456 │ DH001       │ 2024-01-05 │   500000  │
  │ Trần Thị Mai     │ 0901123456 │ DH003       │ 2024-01-20 │   800000  │
  │ Nguyễn Văn An    │ 0912234567 │ DH002       │ 2024-01-12 │   300000  │
  │ Lê Thị Bình      │ 0923456789 │ NULL        │ NULL       │   NULL    │  ← chưa có đơn!
  └──────────────────┴────────────┴─────────────┴────────────┴───────────┘
```

### Dùng LEFT JOIN Để Tìm Hàng "Mồ Côi"

Thủ thuật hay: LEFT JOIN + `WHERE bang_phai.id IS NULL` → Tìm những hàng ở bảng trái **không có** ở bảng phải:

```sql
-- Tìm khách hàng CHƯA CÓ đơn hàng nào
SELECT kh.ho_ten, kh.so_dien_thoai
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
WHERE dh.id IS NULL;       -- ← Chỉ lấy những hàng KHÔNG có đơn hàng

-- Giải thích: Nếu không có đơn hàng khớp,
-- tất cả cột của don_hang sẽ là NULL (kể cả dh.id)
```

> 💡 **Tương đương Excel:** LEFT JOIN giống `=IFERROR(VLOOKUP(...), "Không tìm thấy")` — nhưng thay vì báo lỗi, SQL điền NULL vào và bạn vẫn thấy hàng đó trong kết quả.

## 7.5 RIGHT JOIN và FULL JOIN

### RIGHT JOIN — Lấy Tất Cả Từ Bảng Phải

RIGHT JOIN là ngược lại của LEFT JOIN — lấy tất cả từ bảng **phải** (bảng được JOIN), dù có hay không có khớp ở bảng trái:

```sql
-- Tất cả đơn hàng, kể cả đơn không liên kết với khách nào
-- (Thường xảy ra khi dữ liệu bị lỗi hoặc khách hàng đã bị xóa)
SELECT kh.ho_ten, dh.ma_don_hang, dh.tong_tien
FROM khach_hang kh
RIGHT JOIN don_hang dh ON kh.id = dh.khach_hang_id;
```

> 💡 **Lưu ý thực tế:** RIGHT JOIN ít được dùng vì bạn luôn có thể viết lại thành LEFT JOIN bằng cách **đổi thứ tự hai bảng**. Hầu hết developer chỉ dùng LEFT JOIN cho dễ đọc.

### FULL JOIN — Lấy Tất Cả Từ Cả Hai Bảng

FULL JOIN (hay FULL OUTER JOIN) lấy tất cả từ cả hai bảng — hàng không có khớp sẽ có NULL ở các cột của bảng kia:

```sql
-- Tất cả khách hàng VÀ tất cả đơn hàng
-- Hiển thị NULL nếu không có khớp ở phía nào
SELECT kh.ho_ten, dh.ma_don_hang, dh.tong_tien
FROM khach_hang kh
FULL JOIN don_hang dh ON kh.id = dh.khach_hang_id;
```

## 7.6 Sơ Đồ Tổng Hợp — 4 Loại JOIN

```
  Giả sử có 2 bảng A và B, JOIN theo điều kiện A.id = B.a_id:

  Bảng A có:  id = 1, 2, 3           Bảng B có: a_id = 2, 3, 4
              (3 là có ở cả hai)               (4 chỉ có ở B)

  ┌────────────────────────────────────────────────────────────────────┐
  │  INNER JOIN                                                         │
  │  Chỉ lấy hàng có ở CẢ HAI bảng                                     │
  │  Kết quả: a_id = 2, 3              ○──●●──○                        │
  │           (1 bị bỏ vì không có ở B, 4 bị bỏ vì không có ở A)      │
  ├────────────────────────────────────────────────────────────────────┤
  │  LEFT JOIN                                                          │
  │  Tất cả từ A + phần khớp của B                                     │
  │  Kết quả: id = 1, 2, 3             ●●●──○                         │
  │           (1 có nhưng B không có → cột B = NULL)                   │
  ├────────────────────────────────────────────────────────────────────┤
  │  RIGHT JOIN                                                         │
  │  Phần khớp của A + tất cả từ B                                     │
  │  Kết quả: a_id = 2, 3, 4           ○──●●●                         │
  │           (4 có nhưng A không có → cột A = NULL)                   │
  ├────────────────────────────────────────────────────────────────────┤
  │  FULL JOIN                                                          │
  │  Tất cả từ cả hai bảng                                             │
  │  Kết quả: id/a_id = 1, 2, 3, 4    ●●●●●                           │
  │           (1 và 4 sẽ có NULL ở cột bảng kia)                       │
  └────────────────────────────────────────────────────────────────────┘

  Dùng loại nào?
  ┌──────────────┬──────────────────────────────────────────────────────┐
  │ INNER JOIN   │ Khi chỉ cần hàng có dữ liệu đầy đủ ở cả hai bảng   │
  │ LEFT JOIN    │ Khi cần TẤT CẢ hàng từ bảng chính (bảng trái)       │
  │ RIGHT JOIN   │ Khi cần TẤT CẢ hàng từ bảng phụ (dùng LEFT JOIN     │
  │              │ với thứ tự đổi ngược cho rõ ràng hơn)               │
  │ FULL JOIN    │ Khi cần tất cả hàng từ cả hai bảng                   │
  └──────────────┴──────────────────────────────────────────────────────┘
```

### SELF JOIN — Bảng JOIN Chính Nó

Đôi khi bạn cần kết nối **một bảng với chính nó** — ví dụ khi bảng nhân viên có cột `quan_ly_id` trỏ đến `id` của nhân viên khác.

**So sánh Excel:** Giống VLOOKUP tra cùng một sheet — ô A2 chứa mã, bạn tra cùng sheet đó để lấy tên tương ứng.

```sql
-- Tìm mỗi nhân viên và tên quản lý trực tiếp
SELECT
    nv.ho_ten        AS nhan_vien,
    ql.ho_ten        AS quan_ly
FROM nhan_vien nv
LEFT JOIN nhan_vien ql ON nv.quan_ly_id = ql.id;
```

```
  Kết quả:
  ┌──────────────────┬──────────────────┐
  │ nhan_vien        │ quan_ly          │
  ├──────────────────┼──────────────────┤
  │ Trần Thị Mai     │ Phạm Minh Châu   │
  │ Nguyễn Văn An    │ Phạm Minh Châu   │
  │ Phạm Minh Châu   │ NULL             │  ← Giám đốc, không có quản lý
  └──────────────────┴──────────────────┘
```

> 💡 **Lưu ý:** Dùng LEFT JOIN (không phải INNER JOIN) để giữ lại cả người không có quản lý (giám đốc). Alias (`nv`, `ql`) **bắt buộc** vì cùng bảng — PostgreSQL cần phân biệt "bảng nhan_vien vai trò nhân viên" và "bảng nhan_vien vai trò quản lý".

## 7.7 JOIN Nhiều Bảng

Trong thực tế, bạn thường cần kết nối 3, 4 bảng cùng lúc. Cú pháp: thêm nhiều lần `JOIN ... ON`:

```
  Mối quan hệ giữa các bảng:

  khach_hang ──< don_hang ──< chi_tiet_don_hang >── san_pham
       id        khach_hang_id  don_hang_id           id
                 id             san_pham_id
```

```sql
-- Xem chi tiết đầy đủ: Khách nào → Đơn nào → Mua gì → Giá bao nhiêu
SELECT
    kh.ho_ten               AS ten_khach,
    dh.ma_don_hang,
    dh.ngay_dat,
    sp.ten_sp,
    ct.so_luong,
    ct.don_gia,
    ct.so_luong * ct.don_gia AS thanh_tien
FROM chi_tiet_don_hang ct
JOIN don_hang dh     ON ct.don_hang_id = dh.id
JOIN khach_hang kh   ON dh.khach_hang_id = kh.id
JOIN san_pham sp     ON ct.san_pham_id = sp.id
ORDER BY dh.ngay_dat DESC, kh.ho_ten;
```

> 💡 **Mẹo đọc JOIN nhiều bảng:** Đọc từ bảng trung tâm ra ngoài. Ở đây `chi_tiet_don_hang` là bảng trung tâm — nó liên kết với `don_hang` (lấy thông tin đơn), với `khach_hang` (qua đơn hàng), và với `san_pham` (lấy tên sản phẩm).

### Thứ Tự Viết JOIN

Không có thứ tự bắt buộc — máy sẽ tìm cách tối ưu. Nhưng quy ước để dễ đọc:

```
  Cách 1: Bắt đầu từ bảng chính (bảng bạn quan tâm nhất)
  FROM don_hang dh
  JOIN khach_hang kh ON ...      ← thông tin khách
  JOIN chi_tiet_don_hang ct ON ... ← chi tiết đơn
  JOIN san_pham sp ON ...         ← thông tin sản phẩm

  Cách 2: Theo chuỗi liên kết (bảng A → B → C)
  FROM khach_hang kh
  JOIN don_hang dh ON kh.id = dh.khach_hang_id
  JOIN chi_tiet_don_hang ct ON dh.id = ct.don_hang_id
  JOIN san_pham sp ON ct.san_pham_id = sp.id
```

## 7.8 JOIN + GROUP BY — Combo Mạnh Nhất

Kết hợp JOIN và GROUP BY cho phép tạo báo cáo từ nhiều bảng — điều không thể làm trong một bảng đơn.

### Ví Dụ — Top Khách Hàng

```sql
-- Tổng chi tiêu của mỗi khách hàng
SELECT
    kh.ho_ten,
    kh.so_dien_thoai,
    COUNT(dh.id)            AS so_don_hang,
    SUM(dh.tong_tien)       AS tong_chi_tieu
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
                      AND dh.trang_thai = 'hoan_thanh'  -- ← điều kiện JOIN
GROUP BY kh.id, kh.ho_ten, kh.so_dien_thoai
ORDER BY tong_chi_tieu DESC NULLS LAST;
```

> 💡 **Điều kiện trong ON vs WHERE khi dùng LEFT JOIN:**
> - `AND dh.trang_thai = 'hoan_thanh'` trong mệnh đề `ON` → lọc **trước** khi join, khách hàng không có đơn vẫn xuất hiện (với NULL)
> - `WHERE dh.trang_thai = 'hoan_thanh'` → lọc **sau** khi join, khách hàng không có đơn sẽ bị loại!

### Ví Dụ — Sản Phẩm Bán Chạy Nhất

```sql
-- Top 5 sản phẩm bán được nhiều nhất (theo số lượng)
SELECT
    sp.ten_sp,
    SUM(ct.so_luong)                AS tong_so_luong_ban,
    SUM(ct.so_luong * ct.don_gia)   AS tong_doanh_thu
FROM san_pham sp
JOIN chi_tiet_don_hang ct ON sp.id = ct.san_pham_id
JOIN don_hang dh          ON ct.don_hang_id = dh.id
WHERE dh.trang_thai = 'hoan_thanh'
GROUP BY sp.id, sp.ten_sp
ORDER BY tong_so_luong_ban DESC
LIMIT 5;
```

### Ví Dụ — Nhân Viên Phụ Trách Nhiều Đơn Nhất

```sql
-- Mỗi nhân viên kinh doanh đã xử lý bao nhiêu đơn và tổng giá trị bao nhiêu?
SELECT
    nv.ho_ten,
    nv.phong_ban,
    COUNT(dh.id)            AS so_don_phu_trach,
    SUM(dh.tong_tien)       AS tong_doanh_thu
FROM nhan_vien nv
LEFT JOIN don_hang dh ON nv.id = dh.nhan_vien_id
WHERE nv.dang_lam = TRUE
GROUP BY nv.id, nv.ho_ten, nv.phong_ban
HAVING COUNT(dh.id) > 0
ORDER BY tong_doanh_thu DESC NULLS LAST;
```

## 7.9 Những Lỗi Hay Gặp Với JOIN

### Lỗi 1 — Quên Điều Kiện ON (Cartesian Product)

Đây là lỗi nguy hiểm nhất: khi JOIN mà không có mệnh đề ON, mỗi hàng bảng trái sẽ kết hợp với **mọi hàng** bảng phải:

```
  Bảng A có 100 hàng × Bảng B có 200 hàng = 20,000 hàng kết quả!
  Bảng A có 1,000 hàng × Bảng B có 500 hàng = 500,000 hàng!
```

```sql
-- ❌ NGUY HIỂM: Quên ON — kết quả sẽ phình to bất thường
SELECT kh.ho_ten, dh.ma_don_hang
FROM khach_hang kh
JOIN don_hang dh;            -- Thiếu: ON kh.id = dh.khach_hang_id
-- Mỗi khách sẽ ghép với MỌI đơn hàng!

-- ✅ ĐÚNG: Luôn có ON
SELECT kh.ho_ten, dh.ma_don_hang
FROM khach_hang kh
JOIN don_hang dh ON kh.id = dh.khach_hang_id;
```

### Lỗi 2 — Tên Cột Mơ Hồ (Ambiguous Column)

```sql
-- ❌ LỖI: Cả hai bảng đều có cột "id"
SELECT id, ho_ten, tong_tien
FROM khach_hang kh
JOIN don_hang dh ON kh.id = dh.khach_hang_id;
-- ERROR: column reference "id" is ambiguous

-- ✅ ĐÚNG: Chỉ rõ bảng nào
SELECT kh.id, kh.ho_ten, dh.tong_tien
FROM khach_hang kh
JOIN don_hang dh ON kh.id = dh.khach_hang_id;
```

### Lỗi 3 — NULL Trong Kết Quả LEFT JOIN

Khi dùng LEFT JOIN và sau đó lọc bằng WHERE trên cột của bảng phải, vô tình biến LEFT JOIN thành INNER JOIN:

```sql
-- ❌ SAI: WHERE lọc sau JOIN — loại bỏ hàng NULL từ LEFT JOIN
-- Kết quả: chỉ còn khách có đơn hoàn thành (giống INNER JOIN)
SELECT kh.ho_ten, dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
WHERE dh.trang_thai = 'hoan_thanh';   -- ← loại bỏ hàng NULL!

-- ✅ ĐÚNG: Đặt điều kiện trong ON thay vì WHERE
SELECT kh.ho_ten, dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
                      AND dh.trang_thai = 'hoan_thanh';   -- ← giữ hàng NULL

-- Hoặc nếu muốn giữ NULL + điều kiện thêm trong WHERE:
SELECT kh.ho_ten, dh.tong_tien
FROM khach_hang kh
LEFT JOIN don_hang dh ON kh.id = dh.khach_hang_id
WHERE dh.trang_thai = 'hoan_thanh'
   OR dh.id IS NULL;    -- ← giữ lại cả hàng không có đơn
```

### Lỗi 4 — JOIN Sai Cột (Kết Quả Sai Silently)

```sql
-- ❌ SAI: JOIN nhầm cột — kết quả sai nhưng không báo lỗi!
SELECT kh.ho_ten, dh.tong_tien
FROM khach_hang kh
JOIN don_hang dh ON kh.id = dh.id;   -- ← JOIN id với id thay vì khach_hang_id

-- ✅ ĐÚNG: Kiểm tra logic của ON — phải nối khóa ngoại với khóa chính
JOIN don_hang dh ON kh.id = dh.khach_hang_id
```

> ⚠️ **CẢNH BÁO:** Lỗi số 4 rất nguy hiểm — query chạy được, trả về kết quả, nhưng kết quả **sai hoàn toàn**. Luôn kiểm tra logic của điều kiện ON.

## 7.10 Thứ Tự Thực Thi Với JOIN

JOIN được xử lý ngay sau FROM, trước tất cả các mệnh đề khác:

```
  Thứ tự VIẾT (bạn gõ)               Thứ tự THỰC THI (máy chạy)
  ─────────────────────────────       ────────────────────────────────────────
  SELECT  kh.ho_ten, SUM(...)         1. FROM khach_hang kh
  FROM    khach_hang kh               2. JOIN don_hang dh ON kh.id = ...
  JOIN    don_hang dh ON ...          3. WHERE dh.trang_thai = 'hoan_thanh'
  WHERE   dh.trang_thai = ...         4. GROUP BY kh.id, kh.ho_ten
  GROUP BY kh.id, kh.ho_ten           5. HAVING COUNT(*) > 0
  HAVING  COUNT(*) > 0                6. SELECT kh.ho_ten, SUM(...)
  ORDER BY tong_tien DESC             7. ORDER BY tong_tien DESC
  LIMIT 5                             8. LIMIT 5
```

**Hệ quả quan trọng:**

```sql
-- ✅ Alias bảng (đặt ở FROM/JOIN) có thể dùng NGAY trong ON
FROM khach_hang kh
JOIN don_hang dh ON kh.id = dh.khach_hang_id    -- ✅ dùng alias ngay được

-- ✅ Alias cột (đặt ở SELECT) chỉ dùng được trong ORDER BY
SELECT SUM(dh.tong_tien) AS tong_chi_tieu
FROM don_hang dh
ORDER BY tong_chi_tieu DESC    -- ✅ dùng được alias cột trong ORDER BY
```

## Tổng Kết Tuần 7

### Bảng Tra Cứu Nhanh

| Nhu cầu | SQL |
|---|---|
| Kết nối 2 bảng, chỉ lấy hàng khớp | `FROM a JOIN b ON a.id = b.a_id` |
| Kết nối, lấy tất cả từ bảng trái | `FROM a LEFT JOIN b ON ...` |
| Kết nối, lấy tất cả từ bảng phải | `FROM a RIGHT JOIN b ON ...` |
| Kết nối, lấy tất cả từ cả hai | `FROM a FULL JOIN b ON ...` |
| Tìm hàng không có khớp ở bảng phải | `LEFT JOIN ... WHERE b.id IS NULL` |
| Viết gọn tên bảng | `FROM don_hang dh` (alias) |
| Chỉ rõ cột từ bảng nào | `dh.ma_don_hang`, `kh.ho_ten` |
| Kết nối 3+ bảng | Viết nhiều lần `JOIN ... ON` |

### So Sánh Excel ↔ SQL — Tuần 7

| Excel | SQL |
