## 5.1 WHERE — Lọc Dữ Liệu Theo Điều Kiện

### Câu Chuyện Mở Đầu

Sếp yêu cầu bạn: *"Cho tôi danh sách nhân viên phòng Kinh doanh có lương trên 18 triệu."*

**Với Excel:** Mở bảng → Tab Data → Filter → Click mũi tên cột "Phòng ban" → chọn "Kinh doanh" → Click mũi tên cột "Lương" → Number Filters → Greater Than → nhập 18000000. Xong.

**Với SQL:**
```sql
SELECT ho_ten, luong, phong_ban
FROM nhan_vien
WHERE phong_ban = 'Kinh doanh' AND luong > 18000000;
```

Kết quả: giống hệt, nhưng bạn có thể lưu lại câu lệnh này, tự động hóa, và chạy lại bất cứ lúc nào.

---

### WHERE Hoạt Động Như Thế Nào?

Hãy hình dung bảng dữ liệu như một cái sàng — WHERE là bộ lọc quyết định hàng nào được "lọt qua":

```
  BẢNG nhan_vien (toàn bộ dữ liệu)
  ┌────┬──────────────────┬──────────┬─────────────┐
  │ id │ ho_ten           │ luong    │ phong_ban   │
  ├────┼──────────────────┼──────────┼─────────────┤
  │  1 │ Trần Thị Mai     │ 15000000 │ Kế toán     │
  │  2 │ Nguyễn Văn An    │ 20000000 │ Kinh doanh  │
  │  3 │ Lê Thị Bình      │ 18000000 │ Nhân sự     │
  │  4 │ Phạm Minh Châu   │ 25000000 │ IT          │
  │  5 │ Hoàng Thị Dung   │ 13000000 │ Kế toán     │
  │  6 │ Võ Văn Em        │ 22000000 │ Kinh doanh  │
  └────┴──────────────────┴──────────┴─────────────┘
                         │
             WHERE phong_ban = 'Kinh doanh'
                         │
                    ┌────▼────┐
                    │  LỌC   │  ← Kiểm tra từng hàng: đúng hay sai?
                    └────┬────┘
                         │
  KẾT QUẢ (chỉ hàng thỏa điều kiện)
  ┌────┬──────────────────┬──────────┬─────────────┐
  │ id │ ho_ten           │ luong    │ phong_ban   │
  ├────┼──────────────────┼──────────┼─────────────┤
  │  2 │ Nguyễn Văn An    │ 20000000 │ Kinh doanh  │  ✅ lọt qua
  │  6 │ Võ Văn Em        │ 22000000 │ Kinh doanh  │  ✅ lọt qua
  └────┴──────────────────┴──────────┴─────────────┘
     (Hàng 1, 3, 4, 5 bị loại — không thỏa điều kiện)
```

> 💡 **Quan trọng:** WHERE **không xóa** dữ liệu. Nó chỉ quyết định hàng nào được hiển thị trong kết quả. Bảng gốc hoàn toàn không bị ảnh hưởng — giống hệt Filter trong Excel.

---

### Cú Pháp WHERE

```
┌──────────────────────────────────────────────────────────────────────┐
│                         CÚ PHÁP WHERE                                │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  SELECT  cot1, cot2, ...                                             │
│  FROM    ten_bang                                                    │
│  WHERE   <điều kiện>;          ← Thêm ở đây                         │
│                                                                      │
│  Điều kiện có thể là:                                                │
│  ├── So sánh đơn:    luong > 10000000                                │
│  ├── Kết hợp AND:    luong > 10000000 AND phong_ban = 'IT'           │
│  ├── Kết hợp OR:     phong_ban = 'IT' OR phong_ban = 'Kinh doanh'   │
│  ├── Khoảng giá trị: luong BETWEEN 10000000 AND 20000000            │
│  ├── Danh sách:      phong_ban IN ('IT', 'Kinh doanh', 'Nhân sự')   │
│  ├── Tìm theo mẫu:   ho_ten LIKE 'Nguyễn%'                          │
│  └── Kiểm tra NULL:  email IS NULL                                  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 5.2 Toán Tử So Sánh

Giống như điều kiện bạn nhập khi dùng "Custom Filter" trong Excel:

| Toán tử SQL | Ý nghĩa | Ví dụ | Tương đương Excel Filter |
|---|---|---|---|
| `=` | Bằng | `phong_ban = 'IT'` | "equals" IT |
| `!=` hoặc `<>` | Khác / Không bằng | `phong_ban != 'IT'` | "does not equal" IT |
| `>` | Lớn hơn | `luong > 15000000` | "greater than" 15,000,000 |
| `<` | Nhỏ hơn | `luong < 15000000` | "less than" 15,000,000 |
| `>=` | Lớn hơn hoặc bằng | `luong >= 15000000` | "greater than or equal to" |
| `<=` | Nhỏ hơn hoặc bằng | `luong <= 15000000` | "less than or equal to" |

**Ví dụ thực tế:**

```sql
-- Nhân viên có lương ĐÚNG BẰNG 15 triệu
SELECT ho_ten, luong FROM nhan_vien
WHERE luong = 15000000;

-- Nhân viên KHÔNG thuộc phòng Kế toán
SELECT ho_ten, phong_ban FROM nhan_vien
WHERE phong_ban != 'Kế toán';

-- Nhân viên lương từ 18 triệu trở lên
SELECT ho_ten, luong FROM nhan_vien
WHERE luong >= 18000000;
```

> ⚠️ **Dấu nháy đơn cho chuỗi:** Khi so sánh với text, phải dùng dấu nháy đơn `'...'`
> - ✅ `WHERE phong_ban = 'IT'` — đúng
> - ❌ `WHERE phong_ban = "IT"` — sai (dấu nháy kép là dành cho alias, không phải giá trị)
>
> Với số, **không cần** dấu nháy:
> - ✅ `WHERE luong > 15000000` — đúng
> - ❌ `WHERE luong > '15000000'` — không cần thiết, dễ gây lỗi

## 5.3 So Sánh VARCHAR — Các Bẫy Cần Tránh

### Bẫy 1 — VARCHAR phân biệt hoa thường

Trong Excel, Filter không phân biệt hoa thường — gõ "it" hay "IT" đều ra kết quả như nhau. **SQL thì khác:**

```
  Dữ liệu trong bảng          Câu WHERE                    Kết quả
  ─────────────────────────────────────────────────────────────────────
  phong_ban = 'IT'     │  WHERE phong_ban = 'IT'      │  ✅ Tìm thấy
  phong_ban = 'IT'     │  WHERE phong_ban = 'it'      │  ❌ Không tìm thấy!
  phong_ban = 'IT'     │  WHERE phong_ban = 'It'      │  ❌ Không tìm thấy!
```

```sql
-- ❌ Không trả về kết quả nếu dữ liệu lưu là 'IT'
WHERE phong_ban = 'it'

-- ✅ Cách 1: Viết đúng hoa thường như trong dữ liệu
WHERE phong_ban = 'IT'

-- ✅ Cách 2: Dùng LOWER() để so sánh không phân biệt hoa thường
WHERE LOWER(phong_ban) = 'it'

-- ✅ Cách 3: Dùng ILIKE thay vì = (chỉ dùng được với LIKE pattern)
WHERE phong_ban ILIKE 'it'
```

> 💡 **Nguyên tắc an toàn:** Luôn kiểm tra dữ liệu thực tế trong bảng trước khi viết điều kiện WHERE cho cột text. Chạy `SELECT DISTINCT phong_ban FROM nhan_vien;` để xem đúng format đang lưu.

---

### Bẫy 2 — Khoảng trắng thừa ở đầu/cuối (Trailing Spaces)

Đây là bẫy rất phổ biến khi dữ liệu được import từ Excel hoặc CSV:

```
  Dữ liệu thực tế lưu trong DB    Bạn nhìn thấy    WHERE = ?
  ────────────────────────────────────────────────────────────
  'IT      ' (có 6 dấu cách sau)   IT               ❌ Không khớp!
  '  Kinh doanh' (có 2 dấu trước)  Kinh doanh       ❌ Không khớp!
```

```sql
-- Kiểm tra xem có khoảng trắng thừa không
-- LENGTH đếm cả dấu cách — nếu khác nhau là có vấn đề
SELECT phong_ban, LENGTH(phong_ban) AS do_dai
FROM nhan_vien
GROUP BY phong_ban
ORDER BY phong_ban;

-- Dùng TRIM() để cắt khoảng trắng khi so sánh
WHERE TRIM(phong_ban) = 'IT'

-- Hoặc làm sạch dữ liệu một lần bằng UPDATE (học ở Tuần 9)
UPDATE nhan_vien SET phong_ban = TRIM(phong_ban);
```

---

### Bẫy 3 — So Sánh VARCHAR Với Số (Khác Kiểu Dữ Liệu)

PostgreSQL **nghiêm ngặt hơn Excel** về kiểu dữ liệu. So sánh hai cột khác kiểu có thể gây lỗi hoặc kết quả sai:

```
  Tình huống thực tế:
  Cột "ma_nhan_vien" kiểu VARCHAR lưu giá trị '007', '008', '099'
  Bạn muốn tìm nhân viên có mã > 5

  ❌ SAI — So sánh VARCHAR với số nguyên:
     WHERE ma_nhan_vien > 5
     → Lỗi: operator does not exist: character varying > integer

  ❌ SAI — So sánh VARCHAR theo thứ tự từ điển (không phải số):
     WHERE ma_nhan_vien > '5'
     → '007' < '5' vì '0' < '5' theo bảng chữ cái!
     → Kết quả sai hoàn toàn so với ý định ban đầu!
```

```
  Thứ tự từ điển của VARCHAR (sắp theo ký tự, không phải giá trị số):
  '007' → '008' → '099' → '1' → '10' → '2' → '20' → '9' → '99'
           ↑ Rất khác với thứ tự số: 1, 2, 9, 10, 20, 99
```

```sql
-- ✅ ĐÚNG — Ép kiểu về số trước khi so sánh số
WHERE ma_nhan_vien::INTEGER > 5
-- hoặc
WHERE CAST(ma_nhan_vien AS INTEGER) > 5

-- ✅ ĐÚNG — Nếu muốn so sánh dạng text, đảm bảo format đồng nhất
-- (VD: tất cả đều có 3 chữ số: '001', '005', '099')
WHERE ma_nhan_vien > '005'   -- Lúc này '007' > '005' là đúng ✅
```

```
  Tóm tắt 3 bẫy VARCHAR:
  ┌─────┬──────────────────────────────┬────────────────────────────────────┐
  │ Bẫy │ Vấn đề                       │ Cách xử lý                         │
  ├─────┼──────────────────────────────┼────────────────────────────────────┤
  │  1  │ Hoa/thường không khớp        │ LOWER() hoặc ILIKE                 │
  │  2  │ Khoảng trắng thừa            │ TRIM() khi so sánh                 │
  │  3  │ So sánh VARCHAR với số       │ Ép kiểu ::INTEGER hoặc CAST()      │
  └─────┴──────────────────────────────┴────────────────────────────────────┘
```

## 5.4 AND / OR / NOT — Kết Hợp Nhiều Điều Kiện

### AND — Tất cả điều kiện phải đúng

Giống khi bạn Filter nhiều cột trong Excel — **cả hai** điều kiện phải thỏa:

```
  Điều kiện A: phong_ban = 'Kinh doanh'
  Điều kiện B: luong > 18000000

  ┌──────────────┬──────────────┬──────────────────────────────────┐
  │ Điều kiện A  │ Điều kiện B  │ A AND B → Hàng được chọn?        │
  ├──────────────┼──────────────┼──────────────────────────────────┤
  │ ✅ Đúng      │ ✅ Đúng      │ ✅ Được chọn                      │
  │ ✅ Đúng      │ ❌ Sai       │ ❌ Bị loại                        │
  │ ❌ Sai       │ ✅ Đúng      │ ❌ Bị loại                        │
  │ ❌ Sai       │ ❌ Sai       │ ❌ Bị loại                        │
  └──────────────┴──────────────┴──────────────────────────────────┘
  → AND rất "khắt khe": chỉ 1 trong 4 trường hợp được chọn
```

```sql
-- Nhân viên Kinh doanh VÀ lương trên 18 triệu
SELECT ho_ten, luong, phong_ban
FROM nhan_vien
WHERE phong_ban = 'Kinh doanh' AND luong > 18000000;
```

---

### OR — Ít nhất một điều kiện đúng

```
  Điều kiện A: phong_ban = 'IT'
  Điều kiện B: phong_ban = 'Kinh doanh'

  ┌──────────────┬──────────────┬──────────────────────────────────┐
  │ Điều kiện A  │ Điều kiện B  │ A OR B → Hàng được chọn?         │
  ├──────────────┼──────────────┼──────────────────────────────────┤
  │ ✅ Đúng      │ ✅ Đúng      │ ✅ Được chọn                      │
  │ ✅ Đúng      │ ❌ Sai       │ ✅ Được chọn                      │
  │ ❌ Sai       │ ✅ Đúng      │ ✅ Được chọn                      │
  │ ❌ Sai       │ ❌ Sai       │ ❌ Bị loại                        │
  └──────────────┴──────────────┴──────────────────────────────────┘
  → OR rất "rộng rãi": 3 trong 4 trường hợp được chọn
```

```sql
-- Nhân viên thuộc phòng IT HOẶC Kinh doanh
SELECT ho_ten, phong_ban
FROM nhan_vien
WHERE phong_ban = 'IT' OR phong_ban = 'Kinh doanh';
```

---

### NOT — Đảo ngược điều kiện

```sql
-- Nhân viên KHÔNG thuộc phòng Kế toán
SELECT ho_ten, phong_ban
FROM nhan_vien
WHERE NOT phong_ban = 'Kế toán';

-- Tương đương với:
WHERE phong_ban != 'Kế toán'
```

---

### Kết Hợp AND + OR — Dùng Ngoặc Đơn!

> ⚠️ **CẢNH BÁO: Thứ tự ưu tiên — AND tính trước OR**

Đây là nguồn lỗi logic phổ biến nhất!

```
  Câu hỏi: Lấy nhân viên Kinh doanh hoặc IT có lương trên 20 triệu

  ❌ VIẾT SAI (không có ngoặc):
     WHERE phong_ban = 'Kinh doanh' OR phong_ban = 'IT' AND luong > 20000000

     Máy hiểu là:
     phong_ban = 'Kinh doanh'
     OR
     (phong_ban = 'IT' AND luong > 20000000)

     → Lấy ra: TẤT CẢ nhân viên Kinh doanh (kể cả lương thấp!)
               + nhân viên IT lương trên 20 triệu
```

```
  ✅ VIẾT ĐÚNG (dùng ngoặc để nhóm OR trước):
     WHERE (phong_ban = 'Kinh doanh' OR phong_ban = 'IT') AND luong > 20000000

     Máy hiểu là:
     (phong_ban = 'Kinh doanh' OR phong_ban = 'IT')
     AND
     luong > 20000000

     → Lấy ra: nhân viên Kinh doanh hoặc IT, VÀ có lương trên 20 triệu ✅
```

```sql
-- ✅ Cách đúng — dùng ngoặc để rõ ý
SELECT ho_ten, luong, phong_ban
FROM nhan_vien
WHERE (phong_ban = 'Kinh doanh' OR phong_ban = 'IT')
  AND luong > 20000000;
```

> 💡 **Nguyên tắc vàng:** Khi dùng cả AND và OR trong cùng một WHERE, **luôn luôn dùng ngoặc đơn** để nhóm rõ ràng. Đừng tin vào thứ tự ưu tiên mặc định — dễ nhầm lắm!

## 5.5 BETWEEN / IN — Lọc Khoảng Và Danh Sách

### BETWEEN — Lọc Theo Khoảng Giá Trị

Tương đương "between" trong Excel Custom Filter. Ngắn gọn hơn viết `>= AND <=`:

```
  Thay vì viết dài:                  Có thể viết gọn bằng BETWEEN:
  ┌─────────────────────────────┐    ┌──────────────────────────────────┐
  │ WHERE luong >= 15000000     │    │ WHERE luong                      │
  │   AND luong <= 25000000     │ ←→ │   BETWEEN 15000000 AND 25000000  │
  └─────────────────────────────┘    └──────────────────────────────────┘
                                          ↑ bao gồm cả 2 đầu mút
```

```sql
-- Nhân viên lương từ 15 triệu đến 25 triệu (bao gồm cả 15tr và 25tr)
SELECT ho_ten, luong
FROM nhan_vien
WHERE luong BETWEEN 15000000 AND 25000000;

-- BETWEEN cũng dùng được với ngày tháng
SELECT ho_ten, ngay_vao_lam
FROM nhan_vien
WHERE ngay_vao_lam BETWEEN '2020-01-01' AND '2022-12-31';
```

> 💡 `BETWEEN a AND b` bao gồm cả `a` và `b` (inclusive). Tương đương `>= a AND <= b`.

---

### IN — Lọc Theo Danh Sách Giá Trị

Tương đương chọn nhiều giá trị trong bộ lọc Excel (tick nhiều checkbox):

```
  Excel: Filter → tick ✅ IT, ✅ Kinh doanh, ✅ Nhân sự
                                    ↕ tương đương
  SQL:   WHERE phong_ban IN ('IT', 'Kinh doanh', 'Nhân sự')
```

```sql
-- Nhân viên thuộc một trong các phòng ban này
SELECT ho_ten, phong_ban
FROM nhan_vien
WHERE phong_ban IN ('IT', 'Kinh doanh', 'Nhân sự');

-- Ngắn gọn hơn viết OR nhiều lần:
-- WHERE phong_ban = 'IT' OR phong_ban = 'Kinh doanh' OR phong_ban = 'Nhân sự'
```

**NOT IN — Loại trừ danh sách:**

```sql
-- Nhân viên KHÔNG thuộc phòng Kế toán và Nhân sự
SELECT ho_ten, phong_ban
FROM nhan_vien
WHERE phong_ban NOT IN ('Kế toán', 'Nhân sự');
```

> ⚠️ **Bẫy với NOT IN và NULL:** Nếu danh sách trong `NOT IN` có chứa `NULL`, kết quả sẽ luôn trống! Đây là hành vi đặc biệt của SQL — sẽ giải thích ở mục 5.6.

## 5.6 LIKE — Tìm Kiếm Theo Mẫu

### LIKE Là Gì?

Trong Excel, bạn dùng Filter → "Contains" hoặc "Begins with" để tìm text. LIKE trong SQL làm điều tương tự, dùng 2 ký tự đặc biệt:

```
  Ký tự đặc biệt trong LIKE:
  ┌──────────┬────────────────────────────────────────────────────┐
  │ Ký tự   │ Ý nghĩa                                            │
  ├──────────┼────────────────────────────────────────────────────┤
  │    %     │ Đại diện cho BẤT KỲ chuỗi nào (kể cả chuỗi rỗng) │
  │    _     │ Đại diện cho ĐÚNG MỘT ký tự bất kỳ               │
  └──────────┴────────────────────────────────────────────────────┘
```

### Hình Dung LIKE Qua Ví Dụ

```
  Mẫu LIKE              Ý nghĩa                    Khớp với           Không khớp
  ─────────────────────────────────────────────────────────────────────────────────
  LIKE 'Nguyễn%'   →  Bắt đầu bằng "Nguyễn"   Nguyễn Văn An      Trần Văn An
                                                 Nguyễn Thị Mai     Lê Nguyễn
                                                 Nguyễn             An Nguyễn

  LIKE '%Văn%'     →  Chứa "Văn" ở bất kỳ đâu  Nguyễn Văn An      Trần Thị Mai
                                                 Trần Văn Bình      Phạm Minh Châu
                                                 Văn An

  LIKE '%Mai'      →  Kết thúc bằng "Mai"       Trần Thị Mai       Mai Lan
                                                 Nguyễn Mai         Maise

  LIKE 'L_'        →  "L" + đúng 1 ký tự        Lê                 Le (sai vì e ≠ ê)
                                                 Ly                 Lê Thị (dài hơn)

  LIKE '__00000'   →  2 ký tự + "00000"          AB00000            A00000 (thiếu 1)
                                                 1200000            ABC00000 (thừa)
```

**Ví dụ thực tế:**

```sql
-- Tìm nhân viên họ Nguyễn
SELECT ho_ten FROM nhan_vien
WHERE ho_ten LIKE 'Nguyễn%';

-- Tìm email dùng Gmail
SELECT ho_ten, email FROM nhan_vien
WHERE email LIKE '%@gmail.com';

-- Tìm mã sản phẩm bắt đầu bằng "SP-" và có 2 chữ số tiếp theo
SELECT ma_san_pham FROM san_pham
WHERE ma_san_pham LIKE 'SP-__';
-- Khớp: SP-01, SP-99, SP-AB
-- Không khớp: SP-1 (thiếu 1 ký tự), SP-001 (thừa 1 ký tự)
```

**ILIKE — Không phân biệt hoa thường:**

```sql
-- LIKE phân biệt hoa thường
WHERE ho_ten LIKE 'nguyen%'   -- Không tìm được "Nguyễn Văn An"!

-- ILIKE: không phân biệt hoa thường (PostgreSQL specific)
WHERE ho_ten ILIKE 'nguyen%'  -- Tìm được cả "Nguyễn", "NGUYỄN", "nguyen"...
```

> 💡 **Lưu ý hiệu năng:** `LIKE '%từ_khóa%'` (có `%` ở đầu) chạy chậm hơn trên bảng lớn vì database phải quét toàn bộ bảng. `LIKE 'từ_khóa%'` (chỉ có `%` ở cuối) chạy nhanh hơn vì có thể dùng index. Tuần 10 sẽ học thêm về index.

## 5.7 IS NULL / IS NOT NULL — Lọc Ô Trống

### NULL Là Gì?

Trong Excel, ô trống là ô bạn chưa điền gì vào. Trong SQL, `NULL` là giá trị đặc biệt nghĩa là **"không biết" / "chưa có thông tin"**.

```
  Excel                              SQL
  ┌─────────────┬──────────┐        ┌─────────────┬──────────┐
  │ ho_ten      │ email    │        │ ho_ten      │ email    │
  ├─────────────┼──────────┤        ├─────────────┼──────────┤
  │ Trần Mai    │ (trống)  │   ←→   │ Trần Mai    │  NULL    │
  │ Nguyễn An   │ a@b.com  │        │ Nguyễn An   │ a@b.com  │
  └─────────────┴──────────┘        └─────────────┴──────────┘
```

### Cách Lọc NULL — Không Dùng `=` Được!

```
  ❌ SAI — Không bao giờ dùng = để so sánh với NULL:
     WHERE email = NULL        ← Luôn trả về 0 hàng!
     WHERE email != NULL       ← Luôn trả về 0 hàng!

  ✅ ĐÚNG — Phải dùng IS NULL / IS NOT NULL:
     WHERE email IS NULL       ← Lọc các hàng email bị trống
     WHERE email IS NOT NULL   ← Lọc các hàng email có giá trị
```

**Lý do:** Trong SQL, `NULL` không bằng bất cứ thứ gì — kể cả chính nó (`NULL = NULL` trả về `NULL`, không phải `TRUE`).

```sql
-- Tìm nhân viên chưa có email
SELECT ho_ten FROM nhan_vien
WHERE email IS NULL;

-- Tìm nhân viên đã có email
SELECT ho_ten, email FROM nhan_vien
WHERE email IS NOT NULL;

-- Tìm đơn hàng chưa được giao (ngày giao hàng chưa có)
SELECT ma_don_hang, ngay_dat FROM don_hang
WHERE ngay_giao IS NULL;
```

> 💡 **Tương đương Excel:** Trong Excel Filter, bạn tick vào "(Blanks)" để lọc ô trống. Trong SQL, đó là `IS NULL`.

## 5.8 ORDER BY — Sắp Xếp Kết Quả

### ORDER BY Là Gì?

Tương đương nút Sort trong Excel (A→Z hoặc Z→A). ORDER BY sắp xếp kết quả truy vấn theo một hoặc nhiều cột.

```
  Không có ORDER BY         →   Thứ tự tuỳ ý (database tự quyết định)
  ORDER BY luong ASC        →   Sắp xếp lương tăng dần  (nhỏ → lớn)
  ORDER BY luong DESC       →   Sắp xếp lương giảm dần  (lớn → nhỏ)
```

```
  ┌─────────────────────────────────────────────────────────────────────┐
  │                     CÚ PHÁP ORDER BY                               │
  ├─────────────────────────────────────────────────────────────────────┤
  │                                                                     │
  │  SELECT  cot1, cot2                                                 │
  │  FROM    ten_bang                                                   │
  │  WHERE   dieu_kien                ← Lọc trước                      │
  │  ORDER BY  cot [ASC|DESC];        ← Sắp xếp sau                   │
  │                                                                     │
  │  ASC  = Ascending  = Tăng dần  (A→Z, 1→9, cũ→mới) — MẶC ĐỊNH     │
  │  DESC = Descending = Giảm dần  (Z→A, 9→1, mới→cũ)                 │
  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘
```

### Ví Dụ ORDER BY Đơn Giản

```sql
-- Sắp xếp nhân viên theo lương từ thấp đến cao (tăng dần)
SELECT ho_ten, luong, phong_ban
FROM nhan_vien
ORDER BY luong ASC;

-- Kết quả:
--  ho_ten           | luong    | phong_ban
-- ------------------+----------+-----------
--  Hoàng Thị Dung   | 13000000 | Kế toán      ← lương thấp nhất
--  Trần Thị Mai     | 15000000 | Kế toán
--  Lê Thị Bình      | 18000000 | Nhân sự
--  Nguyễn Văn An    | 20000000 | Kinh doanh
--  Võ Văn Em        | 22000000 | Kinh doanh
--  Phạm Minh Châu   | 25000000 | IT           ← lương cao nhất
```

```sql
-- Sắp xếp theo lương từ cao đến thấp (giảm dần) — xem ai lương cao nhất
SELECT ho_ten, luong, phong_ban
FROM nhan_vien
ORDER BY luong DESC;
```

### Sắp Xếp Theo Nhiều Cột

Khi cột đầu tiên có giá trị bằng nhau, dùng cột thứ hai để phân biệt:

```
  Tình huống: Sắp xếp theo phòng ban (A→Z), trong cùng phòng sắp theo lương cao→thấp

  ORDER BY phong_ban ASC, luong DESC
                 ↑                ↑
        Ưu tiên 1           Ưu tiên 2 (áp dụng khi phong_ban bằng nhau)

  Kết quả:
  ┌──────────────────┬──────────┬─────────────┐
  │ ho_ten           │ luong    │ phong_ban   │
  ├──────────────────┼──────────┼─────────────┤
  │ Phạm Minh Châu   │ 25000000 │ IT          │  ← IT, lương cao nhất
  │ Trần Thị Mai     │ 15000000 │ Kế toán     │  ← Kế toán, lương cao hơn
  │ Hoàng Thị Dung   │ 13000000 │ Kế toán     │  ← Kế toán, lương thấp hơn
  │ Võ Văn Em        │ 22000000 │ Kinh doanh  │  ← Kinh doanh, cao hơn
  │ Nguyễn Văn An    │ 20000000 │ Kinh doanh  │  ← Kinh doanh, thấp hơn
  │ Lê Thị Bình      │ 18000000 │ Nhân sự     │  ← Nhân sự
  └──────────────────┴──────────┴─────────────┘
```

```sql
SELECT ho_ten, luong, phong_ban
FROM nhan_vien
ORDER BY phong_ban ASC, luong DESC;
```

### Sắp Xếp Với NULL

Mặc định trong PostgreSQL: `NULL` được đưa lên **đầu** khi `DESC`, xuống **cuối** khi `ASC`.

```sql
-- Đưa nhân viên chưa có email xuống cuối danh sách
SELECT ho_ten, email
FROM nhan_vien
ORDER BY email ASC NULLS LAST;

-- Đưa nhân viên chưa có email lên đầu danh sách
ORDER BY email DESC NULLS FIRST;
```

## 5.9 Kết Hợp WHERE + ORDER BY + LIMIT

Đây là bộ ba hay dùng nhất trong công việc phân tích thực tế:

```
  Câu hỏi thực tế: "Top 3 nhân viên lương cao nhất trong phòng Kinh doanh"

  Bước 1 — WHERE: Lọc chỉ lấy phòng Kinh doanh
  Bước 2 — ORDER BY: Sắp xếp lương giảm dần (cao → thấp)
  Bước 3 — LIMIT: Chỉ lấy 3 hàng đầu

  ┌──────────────────────────────────────────────────────────┐
  │  SELECT ho_ten, luong                                    │
  │  FROM nhan_vien                                          │
  │  WHERE phong_ban = 'Kinh doanh'   ← Bước 1: lọc        │
  │  ORDER BY luong DESC              ← Bước 2: sắp xếp    │
  │  LIMIT 3;                         ← Bước 3: lấy top 3  │
  └──────────────────────────────────────────────────────────┘
```

**Thêm vài ví dụ hữu ích:**

```sql
-- 5 sản phẩm bán chạy nhất (giả sử có cột so_luong_ban)
SELECT ten_san_pham, so_luong_ban
FROM san_pham
ORDER BY so_luong_ban DESC
LIMIT 5;

-- Đơn hàng gần nhất của khách hàng cụ thể
SELECT ma_don_hang, ngay_dat, tong_tien
FROM don_hang
WHERE ma_khach_hang = 'KH001'
ORDER BY ngay_dat DESC
LIMIT 1;

-- Nhân viên lương thấp nhất trong phòng IT (cần xem xét tăng lương)
SELECT ho_ten, luong
FROM nhan_vien
WHERE phong_ban = 'IT'
ORDER BY luong ASC
LIMIT 3;
```

## 5.10 Thứ Tự Thực Thi Thực Tế

Bạn đã thấy ở Tuần 4 rằng SQL **thực thi** theo thứ tự khác với thứ tự **viết**. Tuần này chúng ta hiểu rõ hơn điều đó ảnh hưởng đến WHERE và ORDER BY như thế nào:

```
  Thứ tự VIẾT (bạn gõ)          Thứ tự THỰC THI (máy chạy)
  ─────────────────────          ──────────────────────────────
  SELECT  ho_ten, luong          1. FROM nhan_vien
  FROM    nhan_vien              2. WHERE luong > 15000000
  WHERE   luong > 15000000       3. SELECT ho_ten, luong
  ORDER BY luong DESC            4. ORDER BY luong DESC
  LIMIT 3                        5. LIMIT 3
```

**Hệ quả quan trọng — Không dùng alias trong WHERE:**

```sql
-- ❌ LỖI: WHERE chạy ở bước 2, SELECT (nơi tạo alias) chạy ở bước 3
--          Alias "luong_sau_thue" chưa tồn tại khi WHERE chạy!
SELECT ho_ten, luong * 0.9 AS luong_sau_thue
FROM nhan_vien
WHERE luong_sau_thue > 13000000;   -- ❌ ERROR: column "luong_sau_thue" does not exist

-- ✅ ĐÚNG: Phải lặp lại biểu thức trong WHERE
SELECT ho_ten, luong * 0.9 AS luong_sau_thue
FROM nhan_vien
WHERE luong * 0.9 > 13000000;     -- ✅ Viết lại biểu thức thay vì dùng alias
```

**Nhưng ORDER BY thì dùng alias được!**

```sql
-- ✅ ĐÚNG: ORDER BY chạy sau SELECT, nên alias đã tồn tại rồi
SELECT ho_ten, luong * 0.9 AS luong_sau_thue
FROM nhan_vien
ORDER BY luong_sau_thue DESC;    -- ✅ Dùng alias được vì ORDER BY chạy sau SELECT
```

```
  Quy tắc nhớ nhanh:
  ┌────────────────────────────────────────────────────────────┐
  │  WHERE    → ❌ KHÔNG dùng alias (chạy TRƯỚC SELECT)       │
  │  ORDER BY → ✅ DÙNG ĐƯỢC alias   (chạy SAU SELECT)        │
  └────────────────────────────────────────────────────────────┘
```

## Tổng Kết Tuần 5

### Bảng Tra Cứu Nhanh

| Nhu cầu | SQL |
|---|---|
| Lọc theo giá trị cụ thể | `WHERE cot = 'gia_tri'` |
| Lọc theo khoảng số | `WHERE cot BETWEEN 100 AND 200` |
| Lọc theo danh sách | `WHERE cot IN ('a', 'b', 'c')` |
| Tìm theo mẫu text | `WHERE cot LIKE 'tiền_tố%'` |
| Lọc ô trống | `WHERE cot IS NULL` |
| Lọc ô có giá trị | `WHERE cot IS NOT NULL` |
| Kết hợp điều kiện (tất cả đúng) | `WHERE dkien1 AND dkien2` |
| Kết hợp điều kiện (ít nhất 1 đúng) | `WHERE dkien1 OR dkien2` |
| Đảo ngược điều kiện | `WHERE NOT dkien` |
| Sắp xếp tăng dần | `ORDER BY cot ASC` |
| Sắp xếp giảm dần | `ORDER BY cot DESC` |
| Sắp xếp nhiều cột | `ORDER BY cot1 ASC, cot2 DESC` |
| Lấy N hàng đầu | `LIMIT N` |

### Checklist Tự Kiểm Tra

Trước khi qua Tuần 6, hãy chắc chắn bạn có thể:

- [ ] Viết WHERE với toán tử so sánh (`=`, `>`, `<`, `!=`)
- [ ] Kết hợp điều kiện với AND, OR và dùng ngoặc đúng chỗ
- [ ] Dùng BETWEEN để lọc khoảng giá trị
- [ ] Dùng IN để lọc theo danh sách
- [ ] Dùng LIKE với `%` và `_` để tìm kiếm text
- [ ] Lọc NULL với IS NULL / IS NOT NULL (không dùng `=`)
- [ ] Sắp xếp với ORDER BY ASC/DESC
- [ ] Sắp xếp theo nhiều cột
- [ ] Kết hợp WHERE + ORDER BY + LIMIT để lấy "Top N"
- [ ] Hiểu tại sao alias không dùng được trong WHERE nhưng dùng được trong ORDER BY

### So Sánh Excel ↔ SQL — Tuần 5

| Excel | SQL |
|---|---|
| Filter cột → chọn giá trị | `WHERE cot = 'gia_tri'` |
| Filter → Number Filters → Between | `WHERE cot BETWEEN a AND b` |
| Filter → Text Filters → Contains | `WHERE cot LIKE '%từ%'` |
| Filter → (Blanks) | `WHERE cot IS NULL` |
| Sort A→Z | `ORDER BY cot ASC` |
| Sort Z→A | `ORDER BY cot DESC` |
| Sort theo nhiều cột (Add Level) | `ORDER BY cot1, cot2` |
| Filter kết quả rồi nhìn 5 hàng đầu | `WHERE ... ORDER BY ... LIMIT 5` |
